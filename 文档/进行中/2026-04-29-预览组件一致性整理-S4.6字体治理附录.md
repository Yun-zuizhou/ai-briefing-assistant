## 1. 补充目的

S4.6 已经完成字体角色收口。本附录负责把规则变成后续迁移时可执行的门禁，避免正式页面替换组件时再次出现“字体看起来乱”的问题。

本附录不新增字体、不扩大视觉风格，只规定：

1. 字体角色怎么用。
2. 哪些写法禁止进入组件库。
3. 进入 S5 和 P4 前如何检查。
4. 正式页面迁移时如何判断一段文字应该归属哪个字体角色。

---

## 2. 字体角色总表

| 角色 | Token | 字体方向 | 使用场景 | 禁用场景 |
| --- | --- | --- | --- | --- |
| 中文展示标题 | `--bookish-font-display-cn` | 中文衬线 | 封面标题、报头主标题、文章型大标题、页面身份标题 | 按钮、Tab、状态、表单、密集列表 |
| 中文正文 | `--bookish-font-body-cn` | 中文无衬线 | 说明文字、正文、普通内容、较长段落 | 报头主标题、强调标题、英文眉标 |
| 中文界面标签 | `--bookish-font-label-cn` | 中文无衬线 | 按钮、Tab、Tag、状态、列表标题、控件标签、看板字段 | 封面大标题、报刊式主标题 |
| 英文眉标 | `--bookish-font-meta-latin` | 拉丁衬线 + 中文回退 | `VOL`、`EDITORIAL`、`AI DESK`、日期编号、英文 meta | 中文按钮、中文标签、中文长句 |

一句话规则：

> 标题负责建立报刊气质，控件负责快速识别，正文负责阅读，英文眉标负责编辑部装饰。

---

## 3. 判断流程

每新增或迁移一个文字样式，先按下面顺序判断：

1. 这段文字是否承担页面身份、栏目身份、文章标题？
   - 是：使用 `--bookish-font-display-cn`
2. 这段文字是否是按钮、Tab、状态、标签、表单、图标旁文本？
   - 是：使用 `--bookish-font-label-cn`
3. 这段文字是否是说明、摘要、正文、普通段落？
   - 是：使用 `--bookish-font-body-cn`
4. 这段文字是否是英文刊号、英文栏目、编号、日期、短 meta？
   - 是：使用 `--bookish-font-meta-latin`

如果一段中文文字同时像标题又像控件，按控件处理。操作清晰度优先于装饰感。

---

## 4. 禁止项

### 4.1 CSS 禁止项

在 `bookish-decor.css` 中禁止继续新增：

```css
font-family: var(--font-serif-cn);
font-family: var(--font-sans-cn);
font-family: var(--font-latin-elegant);
```

必须改用：

```css
font-family: var(--bookish-font-display-cn);
font-family: var(--bookish-font-body-cn);
font-family: var(--bookish-font-label-cn);
font-family: var(--bookish-font-meta-latin);
```

### 4.2 视觉禁止项

1. 中文按钮使用衬线标题字体。
2. 中文标签套用英文拉丁字体。
3. 小字号中文大量增加 `letter-spacing`。
4. 把所有标题、正文、按钮都统一成同一种字体。
5. 为了复古感牺牲表单、按钮、状态的识别效率。

## 5. S5 前检查命令

进入 S5 QA 前，执行：

```powershell
cd apps/web
npm run check:decor-fonts
```

如果当前本机 `npm` 入口不可用，可执行等价兜底命令：

```powershell
cd apps/web
node scripts/check-decor-fonts.mjs
```

通过标准：

1. `bookish-decor.css` 中没有直接调用底层字体 token 的 `font-family`。
2. 检查输出明确显示通过。

如果检查失败，说明某个样式绕过了字体角色，需要先改回 `--bookish-font-*`。

---

## 6. 人工视觉检查清单

每次截图复查时至少检查以下区域：

| 区域 | 应该看到 | 如果不对，通常原因 |
| --- | --- | --- |
| 第一屏封面标题 | 有报刊标题感，但不松散 | `letter-spacing` 过大或字号层级过重 |
| 阶段时间轴 | 状态文字像 UI 标签 | 标签误用了展示标题字体 |
| 按钮组 | 字体清晰、紧凑、可点击 | 按钮误用衬线或行高过松 |
| 英文眉标 | 有 editorial 气质 | 英文 meta 使用了普通中文字体 |
| 中文说明段落 | 易读，不像标题 | 正文误用展示标题字体 |
| R1-R4 样张 | 业务标签与标题分层清楚 | 所有文字都被处理成标题 |

---

## 7. 正式页面迁移口径

后续进入 P4 时，本规则只迁移到复古报刊简报组件相关样式，不要求一次性重写整个正式前端字体系统。

优先迁移对象：

1. 报头组件。
2. 简报卡片。
3. 对话摘要卡。
4. 历史记录列表。
5. 待办行动卡。
6. 成长分析模块标题与字段标签。
7. 设置页表单标签与操作按钮。

暂不强制迁移对象：

1. 旧页面中还未替换为新组件的历史样式。
2. 与复古报刊组件无关的全局基础样式。
3. 已在 `文档/UI设计/2026-04-22-正式前端字体统一规范-基于现有字体.md` 中明确保留的正式前端字体口径。

---

## 8. 退出标准

本附录完成后，S4.6 的补充门禁成立。后续进入 S5 时，字体相关验收必须包含：

1. `npm run check:decor-fonts` 通过；如本机 `npm` 入口不可用，则 `node scripts/check-decor-fonts.mjs` 通过。
2. Playwright 截图中按钮、标签、正文、报头标题字体角色清楚。
3. 新增样式没有绕过 `--bookish-font-*`。
4. P4 正式页面迁移计划引用本附录作为字体门禁。
