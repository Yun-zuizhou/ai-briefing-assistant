## 1. 本稿修正的问题

上一版 R1-R4 布局稿偏“目标态页面设计”，没有充分结合当前页面已经存在的模块。

本稿改为迁移型草图：

1. 先承认当前页面已经有大量可用模块。
2. 不删除有价值功能，只调整归属和信息层级。
3. 记录页从一级沉淀页降级为对话页子页。
4. 待办、成长、我的优先复用现有数据结构和页面区块。
5. 新组件只补缺口，不用新组件覆盖所有旧模块。

## 3. 对话页记录子页迁移草图

### 3.1 迁移原则

对话主页面保持当前对话体验不动。记录作为对话页内的二级视图，不再像 `JournalPage` 一样承接所有沉淀内容。

`ChatRecordsPanel` 不应继续展示一个完整的“想法 + 待办”沉淀中心，而应改成：

1. 对话摘要。
2. 历史对话。
3. 与待办页的轻量连接。

### 3.2 当前模块如何改

| 当前模块 | 新处理 |
| --- | --- |
| 对话中的想法 | 改为“摘要线索”，用于解释摘要来自哪些对话材料 |
| 对话转成的待办 | 不再在记录子页铺完整列表，只显示数量和跳转到待办页 |
| 删除想法 | 短期保留，后续改为对摘要材料的管理动作 |
| 去待办页查看全部 | 保留，改为更明确的“查看对话生成的待办” |

### 3.3 低保真草图

```text
对话页

│ 报头：对话                  │
│ [当前对话] [记录] [历史]     │
```

| 后续跟进 | 保留，靠近待办列表，合并提醒语义 |

## 7. 对组件系统的真实影响

基于迁移型草图，组件库不需要一次补一整套新页面组件。优先补缺口：

| 优先级 | 组件 | 原因 |
| --- | --- | --- |
| C0 | `ChatRecordSummaryCard` | 当前没有 LLM 对话摘要卡 |
| C0 | `ConversationHistoryList` | 当前记录面板没有会话级历史列表 |
| C0 | `ConversationSummaryStatus` | 需要覆盖未生成、生成中、失败、已生成 |
| C1 | `ActionSourceBadge` | 待办页需要清楚表达来源：对话/收藏/手动 |
| C1 | `CollectedInfoActionCard` | 原“收藏待处理”需要转成信息到行动 |
| C2 | `TimeCapsuleSlot` | 成长页新增预留功能，不影响首期主流程 |
| C3 | `SettingsEntryGroup` | 我的页设置化后可整理分组视觉 |

暂不优先新增：

1. 大型全新待办看板。
2. 全新成长报告页面框架。
3. 替代现有 `NavigationEntryCard` 的新卡片系统。
4. 新一级记录页组件。

## 8. 下一步样张顺序

迁移型草图确认后，再进入 `/decor-preview` 样张，不直接改正式页面。

建议顺序：

1. 先做 `ChatRecordsPanel` 迁移样张：摘要 + 历史 + 待办外链。
2. 再做 `ActionsPage` 迁移样张：主行动 + 信息转行动 + 原列表保留。
3. 再做 `GrowthPage` 迁移样张：画像上移 + AI 分析 + 时空胶囊占位。
4. 最后做 `MyPage` 迁移样张：设置中心减法。

完成以上样张并确认后，再恢复组件系统 P4。
