## 1. 总体结论

当前迁移型草图比上一版目标态布局更正确，已经抓住“不是重构，而是当前模块搬家”的方向。

但它还不能直接进入 `/decor-preview` 样张实现。原因是草图目前解决了“模块去哪儿”，还没有完全解决：

1. 用户在每个页面的主路径。
2. 二级导航与 Tab 的层级关系。
3. 哪些内容只是辅助线索，哪些内容是页面主功能。
4. 现有模块迁移后是否会形成新重复。
5. 组件新增是否足够克制。

建议状态：可以作为迁移依据，但需要先修一版“可实现草图 v2”，再进入样张。

## 4. P0 必修问题

### P0-1：对话页“记录/历史”层级重复

当前草图中，对话页顶部有：

```text
[当前对话] [记录] [历史]
```

记录子页内部又有：

```text
[摘要] [历史对话]
```

这会造成两个问题：

1. 用户不知道“历史”和“历史对话”是不是同一件事。
2. 实现时会出现两个路由或两个 Tab 争夺同一内容。

修正建议：

```text
对话页一级视图：
[对话] [记录]

记录内部：
[摘要] [会话]
```

或者：

```text
对话页一级视图：
[对话] [摘要] [历史]
```

建议采用第一种，因为用户提出“记录页应该归属于对话页的子页”，不是要求摘要和历史都变成一级视图。

### P0-2：记录子页出现了第三类主功能

用户已经明确：

> 记录只承担两个功能：对话摘要、历史对话记录。

当前草图中“摘要线索”“对话生成的待办”都被画成独立区块，容易让记录子页再次变成沉淀集合页。

修正建议：

1. “摘要线索”折叠进 `ChatRecordSummaryCard`，作为“依据/来源片段”展开区。
2. “对话生成的待办”只作为摘要卡底部的一行外链，不做独立列表。
3. 历史会话列表里只显示是否“含待办”，不展示待办详情。

推荐结构：

```text
记录子页
├─ 摘要 Tab
│  ├─ 对话摘要卡
│  │  ├─ 摘要状态
│  │  ├─ 要点 / 决策 / 待跟进
│  │  ├─ 依据片段（折叠）
│  │  └─ 对话生成 3 条待办 · 去待办页
│  └─ 最近已摘要会话
└─ 会话 Tab
   ├─ 搜索/筛选
   └─ 历史会话列表
```

### P0-3：`HistoryLogsPage` 去向仍不够确定

草图写了“成长页或历史兼容页”，这对后续路由会形成不确定性。

修正建议：

1. 会话级历史：进入对话页记录子页。
2. 周期性历史归档：进入成长页的“历史回顾”。
3. `/history-logs`：短期保留兼容路由，入口从“我的”移除。

不要把 `/history-logs` 直接塞进对话记录，否则会破坏“记录只承接对话”的边界。

## 5. P1 重要修正

### P1-1：待办页“可转行动的信息”需要限量

当前放在主行动卡之后是合理的，但如果它承接收藏、内容、机会，首屏会再次变成信息流。

修正建议：

1. 首屏最多展示 2 条可转行动信息。
2. 每条必须有明确动作按钮，例如“转成待办”“忽略”“查看来源”。
3. 不展示长摘要，不做收藏列表。
4. 全量收藏仍留在收藏页或兼容路由。

### P1-2：待办页需要明确和 Today 的边界

Today 是“信息/简报推荐”，待办是“行动执行”。  
当前草图写了“信息转行动”，但还没有防止它和 Today 产生重复。

修正建议：

| 来源 | 在 Today 中 | 在待办中 |
| --- | --- | --- |
| 简报内容 | 展示信息价值 | 只展示可执行动作 |
| 收藏内容 | 保留内容本体 | 展示转行动建议 |
| 对话判断 | 可作为今日提醒 | 形成待办/跟进 |

### P1-3：成长页“账号画像卡”命名需要改

当前草图写“账号画像卡”，容易和 My 页账号卡混淆。

修正建议：

1. 成长页使用“用户画像概览”。
2. 我的页使用“账号状态卡”。
3. 不再用“账号画像”这类混合词。

## 6. P2 体验与视觉修正

### P2-1：四个页面需要不同视觉重心

复古报刊主轴不等于所有页面都长一样。

| 页面 | 视觉重心 | 应避免 |
| --- | --- | --- |
| 对话记录 | 档案、摘要、会话列表 | 过多装饰和大卡片 |
| 待办 | 工作台、优先级、来源标签 | 变成收藏信息流 |
| 成长 | 长文本分析、画像证据、报告感 | 变成入口集合 |
| 我的 | 设置、账号、安全 | 叙事化、成长化 |

### P2-2：首屏内容要更克制

移动端首屏建议：

1. 对话记录：报头 + Tab + 一个摘要状态卡。
2. 待办：报头 + 今日主行动 + 最多 2 条可转行动信息。
3. 成长：报头 + 用户画像概览 + 一句话画像。
4. 我的：报头 + 账号卡 + 系统设置首组。

### P2-3：组件新增前先定义复用策略

不要把每个迁移区块都变成新组件。建议：

| 场景 | 先复用 | 再新增 |
| --- | --- | --- |
| 来源标签 | `Tag` | `ActionSourceBadge` |
| 设置入口 | `NavigationEntryCard` | `SettingsEntryGroup` |
| 状态提示 | `PageNoticeCard` / `Tag` | `ConversationSummaryStatus` |
| 历史列表 | 现有 list/article item 样式 | `ConversationHistoryList` |

## 7. 无障碍与状态补充

进入样张前需要补齐以下状态，否则组件实现会漏：

| 页面 | 必补状态 |
| --- | --- |
| 对话记录 | 无历史会话、摘要未生成、生成中、生成失败、重试、摘要过期 |
| 待办 | 无今日行动、无可转行动信息、截止过期、来源丢失、完成后反馈 |
| 成长 | 无画像数据、AI 分析生成中、分析失败、关键词不足、时空胶囊未启用 |
| 我的 | 未登录、设置加载失败、退出登录确认、AI 服务未配置 |

交互要求：

1. Tab 使用明确选中态，触控目标不低于 44px。
2. 摘要生成中状态需要 `aria-live` 或等价反馈。
3. 删除/退出登录等破坏性操作需要二次确认。
4. 历史会话列表需要支持键盘焦点和可识别按钮文案。

---

## 8. 修订后的样张实施顺序

不建议直接做四页高保真样张。应先按风险顺序做低保真：

1. 对话记录子页 v2：解决 Tab 层级和“只有两个功能”的边界。
2. 待办页 v2：验证“信息转行动”不会变成收藏列表。
3. 成长页 v2：验证画像、AI 分析、时空胶囊占位的首屏关系。
4. 我的页 v2：验证减法后入口是否仍可找回。

每个样张只验证结构，不先追求装饰完整度。

---

## 9. 结论

当前草图的核心方向可以保留：

1. 记录归入对话。
2. 待办变成行动工作台。
3. 成长承载画像与 AI 分析。
4. 我的收束为设置中心。

但在进入 `/decor-preview` 前，必须先完成三项修订：

1. 对话页 Tab 层级去重。
2. 记录子页严格只保留“摘要”和“历史会话”两个主功能。
3. 待办页“可转行动的信息”限量并和 Today 划清边界。

完成这些修订后，再进入样张实现会更稳。
