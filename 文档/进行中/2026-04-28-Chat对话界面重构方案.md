# Chat 对话界面重构方案

- 建立日期：2026-04-28
- 文档定位：Chat 界面重新设计的分阶段执行方案
- 前置分析：UI 资产现状报告 + 前端代码审查 + 设计模式研究

---

## 1. 当前状态诊断

### 1.1 代码结构问题

| 文件 | 行数 | 核心问题 |
|------|------|----------|
| `ChatPage.tsx` | 796 | 12 个内联子组件混在单文件中，职责不清 |
| `useChatLogic.ts` | 789 | 18 个 state 变量，recognize + execute 双请求，无取消机制 |
| `chat-page.css` | 491 | `!important` 滥用，硬编码色值，无 reduced-motion |
| `intentParser.ts` | 749 | 客户端正则兜底，测试代码嵌入生产文件，`generateResponse` 未使用 |

### 1.2 体验问题（按严重程度）

| 等级 | 问题 | 影响 |
|------|------|------|
| **P0** | 无流式输出，整个响应一次性构建 | 不像对话，像表单提交 |
| **P0** | 每条消息两次 API 往返（recognize + execute） | 600ms 硬编码延迟 |
| **P1** | 示例提示词硬编码，不个性化 | 每次打开都一样 |
| **P1** | 无会话切换，始终只看最近一条 | 无法回看历史对话 |
| **P1** | 消息 key 用 content 字符串 | 重复内容会渲染异常 |
| **P2** | 无消息编辑/删除 | 打错字无法修正 |
| **P2** | 错误仅内联显示，无 toast | 失败感知弱 |
| **P2** | `formatIntentLabel` 定义两次 | 翻译不一致 |
| **P3** | 无深色模式、无 reduced-motion | 可访问性不足 |

### 1.3 当前界面结构

```

│  Masthead: "对话"                         │

└──────────────────────────────────────────┘
```

## 3. 分阶段执行计划

### 阶段 A：基础重构（不依赖后端改动）

**目标**：拆组件、清理技术债、改善代码结构，界面行为不变。

| 任务 | 内容 | 风险 |
|------|------|------|
| A1 组件拆分 | ChatPage 的 12 个内联子组件拆到 `components/chat/` 独立文件 | 低 |
| A2 State 精简 | useChatLogic 中 18 个 state 合并/删除，消除重复 type 定义 | 中 |
| A3 消息 key 修正 | 从 content 字符串改为 id | 低 |
| A4 删除死代码 | 移除 `generateResponse`、`useChatPanelDrag`、未用 types | 低 |
| A5 CSS 清理 | 移除 `!important`，硬编码色值改为 CSS 变量 | 低 |
| A6 formatIntentLabel 去重 | 合并为单一源 | 低 |

**验收**：`npm run check` 全绿，Chat 页面行为与重构前一致。

### 阶段 B：交互升级（后端小幅配合）

**目标**：流式输出、建议 chips 个性化、会话切换。

| 任务 | 内容 | 依赖 |
|------|------|------|
| B1 合并 API | `recognize + execute` 合并为 `POST /chat/message` 单端点 | Workers 新增 |
| B2 流式输出 | 使用 `ReadableStream` + `EventSource`，消息逐字呈现 | B1 |
| B3 建议 chips | 后端返回 `suggestedActions`，前端渲染为可点击 chips | B1 |
| B4 会话列表 | 侧栏或下拉切换历史会话 | 已有 API（`GET /chat/sessions`） |
| B5 消息操作 | 长按复制、重新生成（仅最后一条）、删除单条 | 后端补充 delete |

**验收**：流式输出可感知，chips 随对话内容变化，可切换会话。

### 阶段 C：卡片化与视觉升级

**目标**：将结构化数据渲染为内嵌卡片，视觉向"数字手账 + 简报"方向升级。

| 任务 | 内容 |
|------|------|
| C1 消息组概念 | 单次助手回复 = 文本块 + 卡片块 + chips 块，共享左侧竖线分组 |
| C2 待办卡片 | 可在对话中直接勾选完成 |
| C3 简报卡片 | Today 数据以卡片形式嵌入对话 |
| C4 视觉升级 | 排版级助手消息（serif 字体、宽松行距）、用户消息紧凑 accent 色气泡 |
| C5 移动适配 | 触控友好的 44px+ 热区，键盘弹起平滑 |

**验收**：卡片与对话自然融合，视觉风格统一。

---

## 4. 不纳入本轮的范围

- **AI 模型接入**：当前对话不是接 LLM，而是意图识别 + 规则执行。接 LLM 是独立立项。
- **语音输入**：阶段 C 之后评估。
- **深色模式**：整体设计系统升级时统一处理。
- **E2E 测试补齐**：阶段 B 完成后补。

---

## 5. 建议启动顺序

**立即启动：阶段 A**（纯前端重构，不改行为，风险最低）

预计工作量：
- A1-A6：1 次对话 session，拆分 + 清理 + CSS 修正
- 验收：`npm run check` 全绿

阶段 B 需要 Workers 侧配合（合并 API + 流式），可作为独立任务卡后续启动。
