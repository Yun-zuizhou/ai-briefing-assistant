# 2026-05-01 Personal Archive 个人沉淀页组 UX 规格

## 1. 页组定位

个人沉淀不是一个页面，而是一组不同来源的沉淀入口。

这组页面要解决的问题：

> 用户看过、说过、保存过、做过的东西，后来还能不能找回来，并且知道它们为什么留在这里。

当前页组：

- `/log`：我的记录；
- `/collections`：我的收藏；
- `/history-logs`：历史日志；
- `/history-brief`：历史简报；
- `/profile`：我的画像；
- `/growth`：成长回看。

本规格先约束前三个高频混淆页。

## 2. 三页边界

### `/log` 我的记录

职责：

- 展示用户主动留下的想法；
- 展示近期行动回声；
- 展示近期收藏和历史轨迹的摘要入口；
- 引导继续记录、去行动、看成长。

不是：

- 不做完整收藏管理；
- 不做完整历史时间线；
- 不替代画像或成长页。

一句话：

> 我主动说过什么、最近推进过什么、有哪些沉淀开始形成。

### `/collections` 我的收藏

职责：

- 管理用户主动保存的内容；
- 支持搜索、打开详情、删除；
- 对机会类收藏提供跟进入口；
- 把“保存对象”转交给阅读详情或待办链路。

不是：

- 不展示所有历史行为；
- 不展示用户所有笔记；
- 不作为行动总表。

一句话：

> 我主动保存了哪些内容，哪些值得继续读或继续处理。

### `/history-logs` 历史日志

职责：

- 按天回看系统自动留下的轨迹；
- 包括阅读、查看、收藏、记录、配置变化等；
- 展示每日归档摘要和原始时间线；
- 作为溯源入口，而不是主动写作入口。

不是：

- 不让用户在这里写日记；
- 不把系统轨迹包装成用户主动表达；
- 不替代周期报告。

一句话：

> 系统按天记下了哪些真实行为，我可以回去查。

## 3. 用户心智

推荐命名：

- 主动表达：`我的记录`
- 主动保存：`我的收藏`
- 自动留痕：`历史日志`
- 周期解释：`历史简报` / 周报 / 月报 / 年报
- 长期理解：`我的画像` / `成长回看`

避免混用：

- 不把 `/log` 叫历史；
- 不把 `/history-logs` 叫日记；
- 不把 `/collections` 叫记录；
- 不把 `/profile` 叫报告。

## 4. 主流程关系

```text
简报 / 阅读详情 / 对话
-> 记录 / 收藏 / 待办 / 历史轨迹
-> 我的记录 / 我的收藏 / 历史日志
-> 我的画像 / 成长回看 / 周期报告
```

具体流向：

- Chat 保存想法 -> `/log`
- Article 收藏内容 -> `/collections`
- 用户阅读、查看、配置 -> `/history-logs`
- 收藏机会转行动 -> `/chat` 确认 -> `/todo`
- 长期沉淀 -> `/profile` 和 `/growth`

## 5. 文案规则

`/log` 使用：

- 主动留下
- 想法
- 行动回声
- 近期沉淀

`/collections` 使用：

- 保存
- 继续阅读
- 转成行动
- 跟进

`/history-logs` 使用：

- 系统留痕
- 历史轨迹
- 按天归档
- 原始时间线

避免：

- 用“记录”统称所有页面；
- 用“真实历史事件”描述普通用户行为；
- 用 emoji 承担正式类型识别；
- 展示内部引用词如“统一引用”。

## 6. 空态规则

空态必须告诉用户“如何产生内容”。

- `/log` 空态：从对话里留下一句话。
- `/collections` 空态：在简报、阅读详情或热点页保存内容。
- `/history-logs` 空态：当天还没有阅读、收藏、记录或配置变化。

## 7. 后续扩展

短期：

- 给 `/history-logs` 增加按类型筛选；
- 给 `/collections` 增加内容类型筛选；
- 给 `/log` 增加“继续编辑/复制到对话”入口。

中期：

- 让 `/profile` 的依据来源可以回跳到对应记录、收藏或历史轨迹；
- 让 `/growth` 汇总这三类沉淀的变化趋势；
- 把用户反馈“不准确”纳入画像生成。
