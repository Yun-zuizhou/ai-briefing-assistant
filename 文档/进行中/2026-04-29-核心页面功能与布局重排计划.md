## 1. 文件定位

本文件是当前页面功能与布局重排的新计划入口。

由于记录、待办、成长、我的四个页面的功能边界发生调整，原组件系统计划中的 P4“正式页面分批迁移与验收”必须后移。当前不能直接把 P0-P3 的样张迁入正式页面，否则会把旧的信息架构问题固化进新组件系统。

本计划先解决页面职责，再回到组件系统 P4。页面设计必须优先按“现有模块迁移”推进，不按全新页面重构推进。进入正式页面迁移前，以迁移型草图 v2 和预览组件一致性整理计划为准。

---

## 2. 为什么需要暂停原P4

原 P4 的前提是：正式页面的信息架构已经稳定，只需要把 P0-P3 的视觉和组件系统迁入。

但当前页面职责已经变化：

1. 记录页不应继续作为独立主页面承载“个人沉淀全集”，它记录的是过去对话的内容和总结，应归属于对话页子页。
2. 待办页不能只是普通 todo 列表，它需要与收集到的信息、机会、跟进对象产生更强关联。
3. 成长页应成为用户画像与 AI 分析的长期承载页，并为“时空胶囊”等附加功能预留空间。
4. 我的页不应继续承接大量成长/沉淀入口，应收束为账号、设置、帮助、系统配置中心。

因此，原 P4 后移，先执行本计划。

## 3. 新页面职责定义

### 3.1 对话页

对话页成为“即时对话 + 对话沉淀”的主入口。

应包含：

1. 当前对话流。
2. 对话页子页：记录。
3. 对话页子页：历史对话。
4. 对话页子页：对话摘要。

记录子页只承担两个功能：

| 功能 | 定义 | 说明 |
| --- | --- | --- |
| 对话摘要 | 调用 LLM 生成过去对话的摘要 | 面向回顾、归纳、复盘 |
| 历史对话记录 | 展示过去对话会话与消息 | 面向检索、继续对话、回看上下文 |

不再承担：

1. 收藏全集。
2. 待办全集。
3. 成长分析。
4. 泛化历史日志。
5. 所有个人沉淀入口。

### 3.2 记录页

记录不再作为一级主页面。

处理建议：

1. `/log` 或 `JournalPage` 进入降级评估。
2. 短期可保留兼容路由，但页面入口应从主导航和“我的”页移除。
3. 未来更合适的落点是 `/chat?view=records` 或 `/chat/records`。
4. 记录页 UI 需要从“个人沉淀总览”改为“对话回顾工作台”。

### 3.3 待办页

待办页需要更独特，不只是任务列表。

新的定位：

> 待办页是把收集到的信息、对话判断和用户目标转成下一步行动的工作台。

应包含：

1. 今日最值得推进的一件事。
2. 来自对话的待办。
3. 来自收藏/内容/机会的信息上下文。
4. 跟进对象与提醒。
5. 行动优先级与完成反馈。

不应继续混乱承载：

1. 收藏内容全集。
2. 泛化推荐内容。
3. 成长打卡叙事。
4. 与 Today 重复的“值得行动”聚合。

### 3.4 成长页

成长页应变成用户长期画像和 AI 分析的核心页面。

新的定位：

> 成长页是系统理解用户、解释用户变化、沉淀长期反馈的地方。

应包含：

1. 用户画像摘要。
2. AI 分析报告。
3. 长期关键词与兴趣变化。
4. 周期报告入口。
5. 用户行为趋势。
6. “时空胶囊”等未来附加功能空间。

需要预留：

1. 时空胶囊。
2. 阶段目标。
3. AI 给未来自己的留言。
4. 长期成长轨迹对比。
5. 用户自定义纪念节点。

### 3.5 我的页

我的页收束为设置型页面。

新的定位：

> 我的页是账号、设置、系统支持和基础配置入口，不再承担成长、记录、历史回顾的核心功能。

应保留：

1. 账号信息。
2. 设置。
3. AI 服务设置。
4. 通知设置。
5. 帮助反馈。
6. 关于。
7. 退出登录。

应移除或降级：

1. 成长回看。
2. 我的画像。
3. 历史日志。
4. 历史简报。
5. 大部分个人沉淀入口。
