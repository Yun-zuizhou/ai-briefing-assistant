## 1. S3 目标

S3 处理的是场景样张之间的职责冲突。

目标不是把样张做得更复杂，而是让 Chat、Today、R1-R4 低保真画板分别承担清楚的页面职责，避免后续正式页迁移时功能再次混乱。

---

## 2. 本次调整结论

### 2.1 Chat 样张

调整前风险：

1. 样张偏单纯聊天流。
2. 没有体现“记录是对话页子页”。
3. “系统简报 / 已执行”容易和 Today、待办混淆。

调整后口径：

1. Chat 主标题收束为“对话”。
2. 增加 `[对话] [记录]` 子页结构提示。
3. 本轮回复标记为“本轮简报 / 已生成”。
4. 行动按钮变为“生成摘要 / 查看记录 / 继续追问”。
5. 可转行动只作为交接，不在 Chat 内完成待办。

### 2.2 Today 样张

调整前风险：

1. Today 中“行动”栏目偏重，容易承接待办页功能。
2. “截止今日 / 高匹配”等表述像待办执行项。
3. 和待办页“信息转行动工作台”的边界不够清楚。

调整后口径：

1. Today 只负责今日信息价值和线索发现。
2. 栏目从“行动”改为“线索”。
3. “值得行动的”改为“可转待办的线索”。
4. 文案强调交给待办页处理，不在 Today 内执行。
5. 主操作保留“打开内容 / 继续追问 / 加入关注”，不出现完成类动作。

### 2.3 R1-R4 页面重排样张

调整前风险：

1. 四个低保真画板缺少迁移状态。
2. 用户无法判断哪些结构已经可迁移，哪些仍需要确认。
3. 记录页摘要卡里“待办已进入待办页”表述过强。

调整后口径：

1. 每个画板增加“可迁移 / 待确认”状态标记。
2. 记录页继续只承担摘要与会话，不增加第三功能。
3. 记录页里的行动表述改为“行动建议可转待办”，保持交接语义。
4. 待办页、成长页、我的页分别标记当前可迁移结构和待确认点。

## 4. 本次没有处理的事项

1. 不迁移正式页面。
2. 不新增业务逻辑。
3. 不改变路由结构。
4. 不把 Today 里的线索直接写入待办。
5. 不抽象新的正式 `SegmentedTabs` 组件。
6. 不重构 `SystemBriefCard`，它仍保留在探索附录。

---

## 5. 遗留给 S4 的问题

S4 进入“预览页体验微调”，优先处理：

1. `/decor-preview` 页面太长，需要更像设计系统文档。
2. 过渡资产和探索附录仍占较大篇幅，可能需要压缩说明。
3. 需要增加“下一步正式页迁移前检查项”。
4. 需要把可迁移组件、暂缓组件、待补组件集中到页面靠前位置。
5. 需要继续减少内联样式和历史探索感。
