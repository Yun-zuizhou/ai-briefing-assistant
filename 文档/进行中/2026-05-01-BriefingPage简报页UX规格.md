# 2026-05-01 BriefingPage 简报页 UX 规格

## 1. 页面定位

`/today` 在代码和路由上仍叫 TodayPage，但产品心智应统一为“简报”。

简报页不是今日任务页，也不是行动决策页。它是一份每天打开的个人报纸：把用户关心领域里今天新发生、被系统收集到的新事件整理成可快速阅读、可追溯原文、可继续追问的简报。

页面的核心问题是：

> 用户今天打开应用后，能不能像读一份报纸一样，快速知道自己关心的领域发生了什么？

## 2. 职责边界

### 2.1 简报页负责

- 展示最重要的摘要；
- 呈现用户关注领域的具体报道；
- 提供原文或详情入口；
- 展示少量大家关注的热点；
- 提供速记入口；
- 支持把速记保存或转交待办；
- 提供围绕本份简报继续对话的入口。

### 2.2 简报页不负责

- 管理待办列表；
- 编排今日行动计划；
- 展示全部热点或全部内容库；
- 承担完整聊天流程；
- 承担收藏、历史、画像、设置的管理工作；
- 把“今天做什么”作为页面主目标。

### 2.3 待办页负责

所有“做什么、何时做、是否完成、是否需要提醒”的生命周期归待办页。

这包括：

- 今日登录；
- 浏览简报；
- 用户主动加入的待办；
- 从速记转成的待办；
- 从报道或对话转成的后续行动；
- 完成状态、延期、提醒和复盘。

简报页可以出现“加入待办”，但它只是把信息或想法转交给待办页，不在本页管理行动。

## 3. 用户目标

### 3.1 主要用户目标

用户来到简报页时，主要想完成四件事：

1. 看到今天最重要的摘要；
2. 浏览自己关注领域的新事件；
3. 少量了解公共热点；
4. 把临时想法快速记录下来，必要时转为待办。

### 3.2 次级用户目标

用户读完简报后，可能继续：

- 打开具体报道；
- 打开原文链接；
- 收藏或保存；
- 围绕某条内容追问；
- 写一条速记；
- 把速记加入待办；
- 从对话页继续深挖。

## 4. 页面成功标准

一个合格的简报页应满足：

- 用户 5 秒内能说出今天简报的头版重点；
- 用户能看出哪些内容来自自己关注领域；
- 用户能打开具体报道或原文；
- 公共热点少而精，不淹没个人关注；
- 速记入口足够轻，不变成复杂表单；
- 对话入口围绕“这份简报”，不是泛泛聊天；
- 行动生命周期清楚流向待办页。

## 5. 信息架构

简报页的信息顺序应固定为：

```text
报头
-> 今日内容摘要
-> 头版重点
-> 关注领域报道
-> 精选热点
-> 速记卡片
-> 对话入口
```

不建议在首屏顶部放重型章节导航。简报可以有目录感，但目录不能抢头版摘要的第一权重。

### 5.1 报头

职责：

- 告诉用户当前是一份简报；
- 展示日期、更新时间、来源数量或生成状态；
- 不承载复杂设置和诊断入口。

建议文案：

- 标题：`简报`
- 副标题：`今天你关心的领域发生了什么`

### 5.2 今日内容摘要

职责：

- 先概括今天整份简报收到了什么；
- 说明今天内容的整体重心；
- 告诉用户这份简报来自哪些关注方向或来源状态；
- 不急着要求用户行动。

规格：

- 这是报头后的第一阅读块；
- 文案应是总述，不是单条新闻标题；
- 可以展示 AI 简报生成状态、来源数量和主题归并；
- 不能比具体报道更长，避免变成报告正文。

### 5.3 头版重点

职责：

- 展示今天最重要的一到两条摘要；
- 说明为什么这条与用户有关；
- 提供查看报道、打开原文、继续追问的入口。

规格：

- 主动作应是“查看报道”或“继续阅读”；
- “继续追问”是次动作；
- “加入待办”只在摘要天然产生行动时出现，且流向待办页；
- 不应把“今天先做什么”写成主语。

### 5.4 关注领域报道

职责：

- 按用户关注领域组织新事件；
- 每个领域展示少量精选报道；
- 明确来源、时间、摘要和原文入口。

规格：

- 每组最多展示 2 到 3 条；
- 优先展示新事件，不做无限推荐流；
- 报道卡片的主入口是详情或原文；
- 推荐理由应解释“为什么与你有关”。

### 5.5 精选热点

职责：

- 少量展示大家都在关注的公共热点；
- 让用户避免错过重要公共议题；
- 不抢关注领域报道的主权重。

规格：

- 最多展示 3 条；
- 热点区不应变成 Hot Topics 全量列表；
- “查看更多热点”可以跳转 HotTopicsPage。

### 5.6 速记卡片

职责：

- 让用户在读简报时快速记下一句话；
- 支持保存；
- 支持加入待办。

规格：

- 速记是轻量输入，不应变成完整 Journal 编辑器；
- “保存”进入记录或沉淀体系；
- “加入待办”进入待办体系；
- 速记可以带上当前简报或当前报道上下文。

### 5.7 对话入口

职责：

- 围绕当前简报继续问；
- 围绕某条报道继续问；
- 带入简报上下文，而不是打开空白聊天。

规格：

- 页面级入口文案应类似 `问这份简报`；
- 报道卡片入口文案应类似 `追问这条`；
- Chat 接收 `sourceTitle`、`sourceContentRef`、`presetInput`。

## 6. 出口设计

| 出口 | 触发点 | 用户意图 | 目标页 | 上下文 |
|---|---|---|---|---|
| 查看报道 | 头版摘要 / 报道卡片 | 阅读详情 | Article | contentRef、title、summary |
| 打开原文 | 报道卡片 | 追溯来源 | 外部链接 / Article 原文动作 | sourceUrl、sourceLabel |
| 继续追问 | 摘要 / 报道卡片 | 围绕内容提问 | Chat | presetInput、sourceContentRef、sourceTitle |
| 查看更多热点 | 精选热点 action | 浏览更多公共热点 | HotTopics | 无 |
| 保存速记 | 速记卡片 | 沉淀想法 | Journal / Log | note、briefingContext |
| 加入待办 | 速记卡片 | 转为行动 | Todo / Actions | note、briefingContext |
| 查看待办 | 待办提示或成功反馈 | 管理行动 | Todo / Actions | todoId 可选 |

## 7. 状态设计

### 7.1 Loading

文案应表达：

```text
正在整理今日简报
```

而不是普通“加载中”。Loading skeleton 应保留报纸结构感：报头、头版摘要、报道卡片。

### 7.2 Error

错误状态应提供恢复路径：

- 重新加载；
- 查看已有历史简报；
- 去热点页兜底浏览；
- 去对话页询问。

### 7.3 Empty

空状态不应说“没有今日行动”。它应说明当前没有足够简报材料，并给出信息输入方向：

- 更新关注领域；
- 查看公共热点；
- 等待下一次同步；
- 手动询问。

### 7.4 Partial AI

AI 简报失败时，页面仍可以展示规则整理结果。文案应表达“已用规则摘要兜底”，不要让用户以为页面坏了。

## 8. 数据契约要求

简报页最依赖这些字段：

- `leadItem`：头版摘要；
- `worthKnowing`：关注领域报道和重要内容；
- `recommendedForYou`：用户关注领域相关报道，不承载 opportunity；
- `aiBriefing`：摘要、主题归并、来源引用和推荐理由，主题归并只基于报道源；
- `extensionSlots`：低权重补充入口；
- `quickNoteEntry`：速记入口；
- `worthActing`：只作为可转交待办的候选，不作为简报页主结构。

优先级应调整为：

1. 头版摘要；
2. 关注领域报道；
3. 精选热点；
4. 速记；
5. 对话入口；
6. 行动转交。

后端和前端都不应让 `worthActing` 抢走简报页的主语。行动可以存在，但行动管理属于待办页。

## 9. 当前实现与规格差距

### 9.1 页面主语已先做低风险纠偏

代码路由和组件名仍保留 `TodayPage`，但页面文案已先转向“简报”：

- 顶部兜底标题改为“简报”；
- lead kicker 改为“头版摘要”；
- `值得知道的` 改为“精选热点”；
- `因你关注而推荐` 改为“关注领域报道”并前移；
- `值得行动的` 改为“可加入待办的线索”并降级到后段。

这一步是低风险纠偏，不等于完成简报页重构。后续只有在命名迁移收益足够明确时，才考虑把技术名从 `TodayPage` 改为 `BriefingPage`。

### 9.1.1 首屏和数据职责已进一步收口

首屏摘要已从“控制面板”收回为纯阅读摘要：

- 摘要框只呈现今日内容摘要和轻量生成状态；
- AI 主题归并不再塞进摘要框，改为关注报道区里的辅助阅读信息；
- extension slots 不再作为摘要区按钮出现；
- 统计条不再压在首屏摘要和头版之间；
- 关注领域报道按关注项分组展示；
- 后端 `recommendedForYou` 只承载报道内容，不再混入 opportunity；
- 后端头版兜底只从 `worthKnowing` 生成，不再用 `worthActing` 补位。

这次治理的重点不是文案，而是把“摘要、头版、关注报道、待办线索”的数据职责拆清楚。

### 9.2 行动区已降级，但数据模型仍带旧痕迹

页面上已不再把行动区命名为“值得行动的”，但数据字段仍是 `worthActing`，交互仍是从简报页跳 Chat 生成待办。

这可以接受为过渡态，但后续不应继续增强简报页内的行动管理。真正的完成、延期、提醒、复盘必须留在待办页。

### 9.3 章节导航可能削弱报纸感

顶部章节导航会让页面像 dashboard 目录。若保留，应在视觉上极轻，或放在头版摘要之后。

### 9.4 速记仍需要真实保存路径

当前速记仍是“去记录”并跳 Chat，尚未完成“直接保存”和“加入待办”的规格要求。后续要明确：

- 保存到记录；
- 加入待办；
- 进入 Chat 继续整理。

三者不能混成同一个按钮。

### 9.5 待办基础任务不应放在简报页管理

今日登录、浏览简报等基础任务应在待办页出现。简报页最多在完成浏览后发出行为事实，不展示任务生命周期。

### 9.6 首屏目录感和视觉噪音已做一轮收口

简报页已继续向“个人报纸”方向推进：

- 移除了报头下方的重型章节导航，避免首屏像 dashboard 目录；
- 摘要框和普通信息框降低边框、虚线和阴影密度；
- 头版重点保留为首屏主要阅读块，用左侧结构线强调主稿；
- 速记入口从“去记录”改为“写速记”，继续带入简报上下文进入 Chat；
- 新增页面级“问这份简报”入口，用于围绕整份简报继续对话；
- 行动区从“可加入待办的线索”降级为“后续线索”，默认只展示少量候选，避免重新变成任务面板。
- 大宽屏下采用“主阅读区 + 辅助入口区”的轻量分栏：主阅读区承载今日摘要、头版重点和关注领域报道；辅助入口区承载精选热点、速记、问简报和后续线索。中等屏和移动端保持单列阅读流，避免在空间不足时硬挤侧栏。
- 768px 以上设备不能继续套 430px 手机壳：平板壳层接近满屏但保留约 24px 安全边距，大宽屏上限为 1120px；900px 以上简报页进入“主阅读区 + 辅助入口区”分栏。1024x600 一类短高横屏还需要压缩报头、底部导航和卡片密度，避免首屏被两侧空白和报头吃掉。
- 主阅读流不再展示推荐解释噪音：`recommendationReason` 和 `topicClusters` 保留为语义层数据，不直接作为独立阅读版块；页面只呈现摘要、头版重点和按关注领域分组的报道。

这一步仍不是最终视觉重构。它解决的是首屏目录感、装饰噪音、行动区权重过高以及所有信息同权重排队的问题；关注报道卡片流、摘要与头版的版式关系、速记的真实保存/加入待办能力，仍需要后续继续细化。

## 11. 验收清单

### 11.1 人工 UX 验收

- 打开页面后，用户能说出“这是一份简报”，不是任务页；
- 5 秒内能识别头版摘要；
- 能找到自己关注领域的具体报道；
- 能打开原文或详情；
- 能区分公共热点和个人关注内容；
- 速记能保存或加入待办；
- 加入待办后能在待办页继续管理；
- 页面不会把“今日要做什么”放在主语位置。

### 11.2 代码契约验收

- `TodayPage.tsx` 不直接调 API；
- 交互逻辑保留在 `useTodayPageLogic`；
- 简报展示组件来自 `components/business` 和 `components/layout`；
- 样式继续归 `styles/today-page.css`；
- 不向 `index.css` 增加简报页样式；
- 涉及保存速记、加入待办、追问简报的关键按钮应补入 `tools/scripts/check-ui-action-contracts.mjs`。

## 12. 后续执行建议

不要马上大改代码结构。

下一步应先做最小纠偏：

1. 把 UX 文档和页面契约统一成“简报”；
2. 检查 UI 文案中是否还把该页说成“今日任务/今日行动”；
3. 降低行动区主权重；
4. 明确速记保存、加入待办、进入对话的三条路径；
5. 再决定是否需要调整页面组件结构。
