# Chat 演示数据接入与缓存修复

- 建立日期：2026-04-29
- 文档定位：Chat 页面演示数据写入云端 D1 + localStorage 脏缓存导致数据错误的问题排查与修复

---

## 1. 问题诊断

### 1.1 现象

对话页加载后显示错误的历史数据，而非预期的演示数据（3 个会话 × 6 条消息）。

### 1.2 根因链

| 环节 | 问题 | 影响 |
|------|------|------|
| **种子 SQL** | `chat_sessions` 未指定 `id`（自动递增），`chat_messages` 硬编码 `session_id=5,6,7` | 外键约束失败，种子数据从未入库 |
| **云端 D1** | user_id=1 残留旧测试 session（id=1，162 条消息） | 即使种子入库，旧数据也会被优先返回 |
| **localStorage 缓存** | `jianbao_chat_state_v1` 保存了 `currentSessionId: 1`，页面初始化直接使用 | `refreshSessionState` 用 `preferredSessionId=1` 去匹配，命中了旧 session |
| **messages 初始化** | `useState(persistedChatState.messages)` 用 localStorage 旧消息做初始值 | 页面首帧渲染旧数据，API 刷新后才能覆盖 |
| **错误可见性** | `chatReadError` 仅展示在 `<details>` 折叠面板中 | 数据加载失败时用户看不到错误提示 |

### 1.3 数据流追踪

```
浏览器 localStorage
  │  currentSessionId: 1, messages: [...旧数据]
  ▼
useChatLogic 初始化
  │  messages = 旧数据（首帧渲染错误内容）
  │  chatReadMode = 'cache'
  ▼
refreshSessionState(preferredSessionId=1)
  │  API: GET /chat/sessions → 4 sessions（含旧 session 1）
  │  sessions.find(s => s.sessionId === 1) → 命中旧 session
  ▼
API: GET /chat/sessions/1/messages → 21 条旧消息
  │  setMessages(旧消息)
  │  UI 持续显示错误数据
```

## 2. 修复措施

### 2.1 D1 数据修复

**a) 清理旧数据**

```sql
DELETE FROM chat_messages WHERE session_id IN (SELECT id FROM chat_sessions WHERE user_id = 1);
DELETE FROM chat_sessions WHERE user_id = 1;
```

结果：162 条消息 + 1 个会话删除。

**b) 修复种子 SQL**（`infra/cloudflare/d1/migrations/seed_demo_chat.sql`）

原问题：
```sql
-- session 未指定 id，自动递增得到 4/5/6
INSERT INTO chat_sessions (user_id, ...) VALUES (1, ...);
-- message 硬编码引用 session_id=5/6/7，外键不匹配
INSERT INTO chat_messages (session_id, ...) VALUES (5, ...);
```

修复后：
```sql
-- 显式指定 session id
INSERT INTO chat_sessions (id, user_id, ...) VALUES (10, 1, ...);
INSERT INTO chat_sessions (id, user_id, ...) VALUES (11, 1, ...);
INSERT INTO chat_sessions (id, user_id, ...) VALUES (12, 1, ...);
-- message 引用一致的 id
INSERT INTO chat_messages (session_id, ...) VALUES (10, ...);
```

**c) 写入**：通过 `wrangler d1 execute --remote --command` 分 6 批逐条执行。

最终 D1 状态：

| id | user_id | session_title | status | messages |
|----|---------|--------------|--------|----------|
| 10 | 1 | 初次设置 | completed | 6 |
| 11 | 1 | 灵感记录 | completed | 6 |
| 12 | 1 | 内容管理 | active | 6 |

### 2.2 前端缓存修复（`useChatLogic.ts`）

| 改动 | 位置 | 说明 |
|------|------|------|
| 模块加载清理 localStorage | 文件顶层 | 检测到旧 `currentSessionId` 时直接 `removeItem` |
| `currentSessionId` 初始值 | `useState(null)` | 不再从 localStorage 读取，由服务端最新 session 决定 |
| `messages` 初始值 | `useState([])` | 不再从 localStorage 读取，避免首帧渲染错误数据 |
| `chatReadMode` 初始值 | `useState('empty')` | 不再预设为 `'cache'` |
| 诊断日志 | `refreshSessionState` | `console.log` 输出 sessions/messages 加载状态 |

### 2.3 错误可见性修复（`ChatPage.tsx`）

在 `PendingConfirmationCard` 之前新增错误横幅：

```tsx
{chatReadError && messages.length === 0 ? (
  <div className="chat-error-banner">
    <span>数据加载失败：{chatReadError}</span>
    <button onClick={() => refreshSessionState(currentSessionId)}>重试</button>
  </div>
) : null}
```

对应 CSS 在 `chat-page.css` 中新增 `.chat-error-banner` 样式。

## 3. 验证结果

刷新后控制台输出：

```
[Chat] Detected stale localStorage session 1, clearing
```

- `preferredSessionId: null` → 不再使用 localStorage 脏缓存
- `Resolved to session: 7 内容管理` → 成功命中 demo 数据
- `6 messages` → 消息数量正确
- 页面显示正常 ✓

## 4. 项目架构认知对齐

本次排查确认了以下架构事实：

```
npm run dev（根目录）
  ├── dev.mjs
  │   ├── prepareLocalD1 → 生产 D1 迁移 + 种子
  │   ├── wrangler dev (8787) → 绑定生产 D1
  │   └── vite dev (5173) → /api/v1 代理到 8787
  │
数据流：浏览器 → Vite proxy → 本地 worker → Cloudflare D1（生产库）
```

- **只有一个后端**：`apps/edge-worker`，本地 `wrangler dev` 直连生产 D1
- 云端 worker (`aibriefing2026.workers.dev`) 当前不可达，不影响本地开发
- Demo 用户体系：`test@example.com`(user_id=1) / `show@example.com`(user_id=2)
- Chat 种子数据未接入正式种子管道（`seeds/generated/`），当前是独立 SQL 文件
