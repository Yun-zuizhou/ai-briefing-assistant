# 2026-05-01 Actions/Todo 待办页 UX 规格

## 1. 页面定位

待办页是行动生命周期管理页。它承接简报、阅读详情、对话和手动输入产生的行动候选，负责让用户知道今天先做什么、后续跟进什么、哪些收藏需要稍后处理。

技术上当前存在 `/actions` 和 `/todo` 语义，产品主语应统一为“待办”。

## 2. 页面负责

- 展示今天最应该推进的一件事；
- 展示今日、未来、已完成待办；
- 标记完成、取消完成、删除待办；
- 展示后续跟进事项；
- 展示稍后处理的收藏内容；
- 展示打卡、提醒和节奏反馈。

## 3. 页面不负责

- 不负责解释简报内容；
- 不负责阅读原文；
- 不负责长对话确认；
- 不负责展示全部收藏库；
- 不负责生成用户画像或报告。

## 4. 信息层级

```text
待办
-> 今天先推进这一件
-> 今日 / 未来 / 已完成 筛选
-> 待办列表
-> 后续跟进
-> 稍后处理的收藏
-> 节奏反馈 / 今日打卡
```

## 5. 上下游关系

上游：

- 简报速记；
- 简报中的后续线索；
- 阅读详情中的 opportunity；
- Chat 里的确认结果；
- 用户手动添加。

下游：

- 完成事实进入 Growth / Profile；
- 行动历史进入 History；
- 周期性进展进入 Reports；
- 未完成事项继续留在待办页。

## 6. 按钮行为

| 动作 | 位置 | 后端状态 | 反馈要求 |
| --- | --- | --- | --- |
| 标记完成 | 待办卡片 | todo status | 成功后刷新列表 |
| 删除 | 待办卡片 | delete todo | 失败回显错误并刷新 |
| 今日打卡 | 节奏反馈 | check-in | 完成后 disabled |
| 主推进 | 顶部主卡 | todo 或 deepLink | 如果是 todo，直接完成；否则跳转来源 |
| 建议项 | 主卡下方 | deepLink | 保留上下文 |

## 7. 当前实现与差距

已完成：

- 页面主语从“行动”收口为“待办”；
- 顶部 meta 改为“今日推进、后续跟进、稍后处理”；
- 空状态文案明确上游来自简报、阅读详情和对话；
- 收藏区改名为“稍后处理的收藏”，避免误解成完整收藏库。

仍有差距：

- `/actions` 与 `/todo` 的路由语义还没有完全统一；
- 主推进按钮对 todo 会直接标记完成，缺少二次确认或撤销反馈；
- 待办卡片没有展示来源标题或来源内容上下文；
- 从简报速记直接生成待办的闭环尚未完成。

## 8. 验收清单

- 用户能判断这里是“要做什么”的地方；
- 用户能看到今天最应该推进的一件事；
- 用户能区分今日、未来、已完成；
- 从简报/阅读/对话来的行动保留来源上下文；
- 完成、删除、打卡都有反馈；
- 页面不承接阅读详情或简报解释。
