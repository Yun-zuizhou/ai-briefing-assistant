# P6 周期报告 LLM 文本块接入产出

日期：2026-04-30

## 本次目标

把周报/月报从纯规则文案升级为“规则结构 + LLM 解释文本块”的混合报告。

核心边界：

- LLM 不生成整份报告 payload。
- LLM 不改变统计、主题趋势、成长轨迹等结构化字段。
- LLM 只生成可校验的解释文本块。
- LLM 文本块必须从服务端提供的 `evidenceRefs` 中选择证据。
- Provider 失败、超时、JSON 非法时保留规则报告，不阻断报告页。

## 已完成内容

### 1. 新增报告 LLM 文本块服务

新增文件：

- `apps/edge-worker/src/services/reports/llm-blocks.ts`

能力：

- 构建 `generate_report_blocks` prompt。
- 输入周报/月报规则 payload、数据质量、主题趋势、成长轨迹、候选 `evidenceRefs`。
- 要求模型只返回严格 JSON。
- 输出字段：
  - `trendExplanation`
  - `periodSummary`
  - `nextActions`
  - `dataNote`
  - `evidenceIndexes`
- 只允许 `evidenceIndexes` 引用候选证据数组下标。
- 解析失败时回退规则报告里的 `trajectory.description/title/suggestions`。
- 调用走 `loggedChatCompletion`，写入 `llm_invocations`。
- 已接入 `validateOutput` 输出校验：Provider HTTP 成功但输出为空/非 JSON 时，统一记录为 `status=error`、`error_code=invalid_model_output`，不再误记为成功。

### 2. 报告路由接入

更新文件：

- `apps/edge-worker/src/routes/reports.ts`
- `apps/edge-worker/src/services/reports/index.ts`

接入范围：

- `GET /api/v1/reports/weekly`
- `GET /api/v1/reports/monthly`

新增行为：

- 当无缓存或传入 `?refresh=1` 时，先构建规则报告 payload。
- 若用户已配置 AI provider，则尝试生成 LLM 文本块。
- LLM 成功时，将文本块合入 payload：

```json
{
  "generationSource": "llm",
  "llmBlocks": {
    "version": "llm-report-blocks-v1",
    "provider": "deepseek",
    "model": "deepseek-v4-flash",
    "trendExplanation": "...",
    "periodSummary": "...",
    "nextActions": ["..."],
    "dataNote": "...",
    "evidenceRefs": []
  }
}
```

- LLM 失败时返回规则报告，`generationSource` 保持 `rules`。
- `reports` 表同步写入：
  - `generation_source`
  - `provider_name`
  - `model_name`
  - `evidence_refs_json`

### 3. 验收用刷新参数

新增查询参数：

- `GET /api/v1/reports/weekly?refresh=1`
- `GET /api/v1/reports/monthly?refresh=1`

用途：

- 绕过当前周期缓存，重新生成报告。
- 便于本地/人工验收 LLM 文本块。
- 不改变已有 `report_id` 查询行为。
