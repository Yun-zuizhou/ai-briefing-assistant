# 2026-05-01 Chat 配置系统信息链路 UX 规格

## 1. 链路定位

“对话 -> 配置系统信息 -> 配置成功”是正式主链路，不是普通聊天建议。

用户可以在 Chat 中直接说出配置意图，例如调整关注领域、移除关注、修改简报推送时间。系统必须先识别配置项，再确认写入，最后给出明确的配置成功反馈和可验证入口。

## 2. 链路步骤

```text
用户在 Chat 输入配置意图
-> 系统识别为系统配置类意图
-> 前端展示待确认卡片
-> 用户确认配置类型
-> 后端写入配置事实
-> Chat 展示配置结果卡
-> 用户可跳转到对应页面验证
```

## 3. 当前纳入配置链路的意图

- `add_interest`：新增关注领域；
- `remove_interest`：移除关注领域；
- `set_push_time`：调整简报推送时间。

暂不纳入：

- AI Provider API Key 配置；
- 账号、安全、登录态变更；
- 删除数据；
- 通知免打扰等尚未完成 Chat 写入契约的设置。

这些配置需要更严格的表单、加密或二次验证，不能先塞进 Chat。

## 4. 交互要求

配置类意图必须满足：

- 不直接静默写入；
- 必须展示“请你确认”；
- 确认卡要说明这会修改系统配置；
- 成功后文案必须包含“配置成功”或等价表达；
- 成功结果必须包含验证入口，例如简报页或通知设置页；
- 失败时不能假装配置成功。

## 5. 数据与页面去向

| 意图 | 写入对象 | 成功入口 | 用户验证 |
| --- | --- | --- | --- |
| `add_interest` | `user_interests` | `/today` | 简报推荐方向变化 |
| `remove_interest` | `user_interests` | `/today` | 简报减少该方向 |
| `set_push_time` | `user_settings` + `briefing_schedules` | `/notification-settings` | 通知设置显示时间 |

## 6. 当前实现状态

已完成：

- Chat 空状态和首屏提示加入系统配置示例；
- `add_interest`、`remove_interest`、`set_push_time` 写入前必须确认；
- 确认卡说明会修改系统配置；
- 配置成功卡从“本轮摘要”区分为“配置结果”；
- 成功文案明确“配置成功”；
- 关注配置成功后跳 `/today`；
- 推送时间配置成功后跳 `/notification-settings`；
- worker 测试覆盖“未确认不写入”和“确认后成功写入”。

仍有差距：

- 通知设置页是否立即展示最新时间还需要人工验收；
- Chat 还不能安全配置 AI Provider 密钥；
- 关注领域的自由文本抽取仍偏关键词，复杂表达可能需要 LLM 分类；
- 成功后没有自动刷新当前简报，只提供验证入口。

## 7. 验收清单

- 输入“我想关注 AI 和远程工作”后先出现确认，而不是直接写入；
- 确认“更新关注”后显示配置成功；
- 成功结果能跳到简报页；
- 输入“以后每天早上 8 点发简报”后先出现确认；
- 确认“调整推送时间”后显示配置成功；
- 成功结果能跳到通知设置；
- 任一写入失败时，不能显示成功。
