# 2026-05-01 Profile 我的画像页 UX 规格

## 1. 页面定位

`/profile` 是“我的画像”详情页。

它不是成长首页，也不是报告页，更不是调试 LLM 生成结果的页面。它负责把用户已经留下的事实整理成一个可检查、可更新、可追溯的个人理解。

一句话定位：

> 让用户知道系统现在如何理解自己，以及这个理解来自哪些真实行为。

## 2. 所属主流程

```text
简报阅读
-> 收藏 / 速记 / 待办 / 对话
-> 个人沉淀
-> 我的画像
-> 成长回看 / 报告
-> 反哺后续简报
```

`/profile` 接收前面页面沉淀下来的事实，不直接制造每日内容，也不直接管理行动。

## 3. 与相邻页面的关系

### `/me`

`/me` 是个人中心，负责入口和账号概览。它可以展示“我的画像”入口，但不内联画像内容。

### `/growth`

`/growth` 是成长概览，负责长期变化、周期报告入口和趋势导航。它可以引用画像摘要，但不展开画像依据。

### `/profile`

`/profile` 是画像详情，负责：

- 当前画像说明；
- 近期行为分布；
- 数据概览；
- 关键判断；
- 成长关键词；
- 依据来源；
- 手动更新画像。

### `/settings`

`/settings` 管系统配置，不管理画像解释。

## 4. 页面层级

推荐层级：

1. 页头：`我的画像`，说明这是个人理解页。
2. 更新状态卡：说明画像是否可更新、是否由 AI 生成、当前模型或基础规则状态。
3. 近期行为分布：让用户先看到画像不是凭空生成。
4. 数据概览：记录、收藏、待办、关注领域。
5. 画像说明：自然语言总结。
6. 关键判断：可追溯的判断点。
7. 成长关键词：轻量标签。
8. 依据来源：展示来源类型、标题、原因。

## 5. 文案规则

面向用户的页面文案避免使用：

- `LLM`
- `规则画像`
- `证据`
- `调试`
- `payload`
- `生成链路`

可以使用：

- `画像`
- `画像说明`
- `基础画像`
- `依据来源`
- `关键判断`
- `近期行为`
- `更新`

原因：画像页需要建立信任，内部技术词会让用户感觉自己在看系统后台。

## 6. 数据真实性规则

画像页必须保持“可追溯”：

- 有依据时，展示依据来源；
- 没有依据时，明确说暂无可追溯依据；
- 画像更新失败时，不展示“已更新”；
- AI 不可用时，可以展示基础画像，但必须承认它是基础画像；
- 不为了好看虚构行为、兴趣或来源。

## 7. 交互规则

画像更新按钮：

- 只负责重新生成/刷新画像；
- 不跳转到 AI Provider；
- 不直接修改关注领域；
- 不把用户带到待办或报告页。

可以后续增加的入口：

- `查看成长回看`：去 `/growth`；
- `调整关注领域`：去 `/interest-config` 或 Chat 配置确认链路；
- `查看依据详情`：去 Article / Collections / History 对应来源。

这些入口必须作为明确操作出现，不能让整张卡片隐式跳转。

## 8. 空态

新用户或低数据用户：

- 展示基础画像；
- 告知需要阅读、收藏、记录、待办后画像才会更完整；
- 不把空态包装成已经很准确的结论。

推荐空态：

`当前画像还很轻。阅读简报、收藏内容、记录想法或完成待办后，这里会逐渐形成更稳定的个人理解。`

## 9. 后续治理点

短期：

- 继续减少内部技术词；
- 为依据来源增加可点击跳转；
- 增加画像更新时间。

中期：

- 让画像说明区明确区分“系统观察到的事实”和“系统推断”；
- 允许用户反馈“这不准确”；
- 把用户反馈纳入下一次画像更新。
