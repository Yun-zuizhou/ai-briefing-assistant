# 信息密集页设计模板

适用页面：简报、报告、热点、成长、画像，以及任何同时包含摘要、内容列表、元数据、入口按钮和后续动作的页面。

## 1. 先定义阅读流，不先摆 UI

信息密集页不是字段陈列。后端和语义层可以保留完整数据，但页面必须先把数据翻译成用户阅读顺序。

固定阅读顺序：

1. 定位层：这是什么页面、什么日期或周期。
2. 总述层：整体发生了什么。
3. 主稿层：最重要的一条内容。
4. 分组阅读层：按用户能理解的主题、领域或任务分组。
5. 辅助入口层：对话、速记、保存、待办、更多列表。

## 2. 主阅读流只放用户要读的内容

可以进入主阅读流：

- 面向用户的摘要；
- 一条主稿；
- 分组后的报道、证据或结论；
- 直接阅读所需的来源名称和时间；
- 明确的主动作，例如查看报道、查看报告、打开原文。

不能进入主阅读流：

- provider、model、demo seed、template name；
- ranking score、raw recommendation reason、processing trace；
- “因为你关注了……”这类重复解释；
- 与当前阅读无关的待办生命周期；
- 为开发调试准备的字段。

## 3. 辅助入口不能抢主阅读

辅助入口负责承接行为，不负责解释全部信息。它可以包括：

- 问这份内容；
- 写速记；
- 保存；
- 转待办；
- 查看更多；
- 进入详情页。

辅助入口在宽屏可放侧栏，在窄屏放主阅读流之后。辅助入口的视觉权重必须低于主稿和分组阅读。

## 4. 分栏规则

- 767px 以下：单列。
- 900px 以上：可使用主阅读区 + 辅助入口区。
- 1280px 以上：最多放宽到系统壳层上限，不能无限拉长正文。

分栏不是为了装满空间，而是为了让主阅读和辅助入口分工清楚。

## 5. 工程入口

新增或大改信息密集页时，先使用模板：

```bash
npm run generate:template -- information-page --Feature Briefing --feature briefing --dry-run
```

模板位置：

- `tools/templates/information-page/InformationPage.template.tsx`
- `tools/templates/information-page/useInformationPageLogic.template.ts`
- `tools/templates/information-page/InformationPageStyle.template.css`

页面逻辑 hook 必须把原始数据翻译成：

- `overview`
- `headline`
- `groupedReports`
- `auxiliaryEntries`
- `uiBoundaries`

JSX 不应该直接消费原始后端字段来拼版块。

## 6. 审核问题

每次改信息密集页前，先回答：

1. 这条信息属于总述、主稿、分组阅读、辅助入口，还是隐藏处理数据？
2. 用户看到它后能做什么？
3. 它是否和页面上另一处信息重复？
4. 它是否暴露了系统加工过程，而不是用户需要的结果？
5. 它在手机、平板、宽屏上的主次关系是否一致？
