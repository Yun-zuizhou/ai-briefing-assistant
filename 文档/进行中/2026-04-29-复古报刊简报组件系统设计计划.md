## 2. 为什么切到这条主线

当前 UI 组件库已经开始形成，但仍处于“样张探索”阶段，尚未成为正式页面的统一设计系统。

主要问题：

1. **设计主轴容易跑偏**：当前新增组件仍以 `Bookish` 命名和“国风书卷”注释为主，但产品核心能力是 AI 简报，不是国风展示。
2. **图标路径分裂**：`BookishIcon.tsx`、`BookishIconSet.tsx`、`components/icons/*.svg`、`lucide-react` 四套图标来源并存。
3. **组件分层未收口**：`ui`、`decor`、`business/chat` 都有可复用组件，但职责边界和正式迁移顺序不清楚。
4. **预览页还不是设计系统文档**：`/decor-preview` 已能表达方向，但缺少 token、图标规范、报头 variants、状态矩阵和真实场景样张。
5. **正式页面尚未充分消费组件库**：当前正式页面主要使用 `Button / Tag / Switch`，新增装饰组件多数仍只在预览页使用。

因此需要先把“图标与组件设计系统”作为独立子主线收口，再进入正式页面迁移。

## 3. 当前设计主轴

### 3.1 一句话定义

当前组件系统应定义为：

> 服务 AI 简报助手的复古报刊式移动端组件系统，以简报、编辑部、纸张和档案为主视觉，国风几何符号仅作为辅助点缀。

### 3.2 主关键词

- 复古报刊
- AI 简报
- 编辑部排版
- 纸张 / 档案
- 温暖、克制、可日用
- 信息秩序强于装饰冲击

### 3.3 辅助关键词

- 国风几何
- 菱形
- 星点
- 灯笼
- 书卷

辅助关键词只能用于小型图标、分隔点、标题点缀，不承担页面主视觉。

### 3.4 禁止方向

1. 不做水墨、传统纹样、复杂古风、节庆灯笼化。
2. 不做复古报纸展示稿，不把页面变成报纸海报。
3. 不做通用 SaaS 蓝白科技风。
4. 不做复杂插画、渐变、阴影、高光、3D、拟物纹理。
5. 不让装饰压过信息层级和主任务。

## 4. 当前真实现状

### 4.1 资产分层

| 层级 | 位置 | 当前状态 | 判断 |
| --- | --- | --- | --- |
| 基础 UI | `apps/web/src/components/ui` | `Button / Tag / Switch` 已大量使用，`Card / Input / EmptyState / ErrorToast / LoadingSpinner` 使用不足 | 需要补状态矩阵并推动页面复用 |
| 布局 | `apps/web/src/components/layout` | `PageLayout / Masthead / SecondaryHeader` 是正式页面骨架 | 报头 variants 需要设计系统化 |
| 装饰组件 | `apps/web/src/components/decor` | 已有 `BookishIcon / BookishSymbol / PaperButton / BookishCard / StatusBadge` 等 | 需要主轴重命名或语义降级 |
| Chat 组件 | `apps/web/src/components/chat` | 已拆出 Chat 页组件 | 需要用组件系统重新打样，而不是直接迁移 |
| 图标资产 | `BookishIcon.tsx / BookishIconSet.tsx / components/icons / lucide-react` | 四套来源并存 | 必须确定唯一正式路径 |
| 预览页 | `apps/web/src/pages/DecorPreviewPage.tsx` | 已能展示复古报刊简报方向 | 需要升级为设计系统样张页 |

### 4.2 当前已成立的设计决策

1. 产品核心不是“国风书卷”，而是“AI 简报”。
2. 视觉主轴是复古报刊、编辑部、纸张、档案。
3. 国风元素只做辅助，不能本末倒置。
4. 图标必须执行零容错规则：
   - 24x24
   - 2px stroke
   - 单线描边
   - round cap / round join
   - 主线色 `#8B5A2B`
   - 背景色 `#F7F3EB`
   - 禁止渐变、阴影、高光、纹理、填充型功能图标
5. 正式设计目标仍是移动端，桌面浏览器只承担开发调试和演示预览。

## 8. P1：图标系统一期 + 报头系统一期

### 8.1 目标

建立正式图标路径和报头组件设计标准，停止图标来源继续分裂。

### 8.2 图标系统一期

#### 正式候选命名

建议新增或重命名为：

- `EditorialIcon`
- `EditorialSymbol`
- `EditorialIconWrapper`

`BookishIcon` 可作为过渡实现，但设计语义上应降级为辅助装饰，不再代表整个系统。

#### 第一批正式图标

| 图标 | 语义 | 用途 |
| --- | --- | --- |
| `briefing` | 简报 | Today / 简报条目 |
| `inbox` | 收件 / 归档 | 收藏、归档、收件箱 |
| `chevron-diamond` | 进入 | 展开、下一步 |
| `search` | 搜索 | 搜索输入 |
| `refresh` | 刷新 | 重试、更新 |
| `bookmark` | 收藏 | 内容沉淀 |
| `send` | 发送 | Chat 输入 |
| `archive` | 归档 | 会话/内容归档 |
| `bell` | 提醒 | 通知、节点 |
| `settings` | 设置 | 系统设置 |
| `close` | 关闭 | 弹窗、取消 |
| `arrow-left` | 返回 | 二级页返回 |

#### 图标治理

| 资产 | 处理建议 |
| --- | --- |
| `BookishIcon.tsx` | 短期保留，作为一期自绘图标基础 |
| `BookishIconSet.tsx` | 暂停扩展，评估拆分或归档 |
| `components/icons/*.svg` | 不继续直接使用，后续统一归档或转入正式 Icon 组件 |
| `lucide-react` | 作为临时补位；正式高频图标逐步替换为自绘图标 |

### 8.3 报头系统一期

#### variants

| Variant | 用途 | 页面 |
| --- | --- | --- |
| `briefing` | 今日简报主报头 | Today |
| `chat` | 对话页报头 | Chat |
| `compact` | 二级页压缩报头 | Article / Collections / Settings |
| `report` | 周期报告页 | Weekly / Monthly / Annual |
| `plain` | 表单 / 设置弱装饰页 | Login / Settings |

#### 报头信息层级

1. 刊号 / 日期 / 栏目
2. 主标题
3. 副标题分隔线
4. meta / right action

### 8.4 验收条件

1. `/decor-preview` 展示第一批正式图标。
2. 图标线条、色值、尺寸和安全边距一致。
3. 报头 variants 有至少 3 个样张：`briefing / chat / compact`。
4. 明确 `lucide-react` 和自绘图标边界。

## 10. P3：Today 简报样张 + 页面迁移策略

### 10.1 目标

验证“复古报刊简报系统”是否真正服务核心功能，而不是只服务 Chat 或装饰预览。

### 10.2 Today 简报样张

样张内容：

1. 今日刊头
2. 简报摘要
3. 信息条目
4. 行动入口
5. 收藏 / 归档 / 追踪图标
6. 空状态
7. 加载态
8. 错误态

### 10.3 页面迁移策略

页面迁移不一次性铺开，按以下顺序：

1. `Chat`：低成本表达入口，验证输入栏、消息卡、状态卡
2. `Today`：核心简报入口，验证报头、摘要卡、信息条目
3. `Actions`：验证行动卡和状态标签
4. `Journal`：验证记录与引用块
5. `Reports`：验证 report variant 报头和周期卡片
6. `Settings`：验证弱装饰表单页

### 10.4 验收条件

1. Today 样张明确体现 AI 简报主功能。
2. 图标和组件在 Chat / Today 两个核心场景中均可用。
3. 形成正式页面迁移清单。
