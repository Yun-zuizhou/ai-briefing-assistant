# UI 破局：组件桥接与路由解耦计划

- 文档状态：执行中
- 建立日期：2026-04-30
- 背景：decor 组件库与正式业务页面长期断层，预览样张无法稳定迁入正式页
- 方法来源：`Design System Architect`、`Visual Designer`、`frontend-design`

---

## 1. 核心判断

当前 UI 困境不是缺少组件，而是缺少“桥接层”。

现状是：

1. `components/decor/` 像展厅，只在 `/decor-preview` 中完整展示。
2. 正式页面仍以页面级 CSS 和路由页 JSX 拼装为主。
3. 样张没有升级为正式 scene，因此迁移时只能拆零件，导致报头、装饰线、纸面、状态变换全部失真。
4. 路由页同时承担数据、URL、布局、滚动、报头和底部输入，视觉设计被路由结构锁死。

破局原则：

> 样张必须上升为可复用 Scene/Shell；路由只传数据和事件，不能继续手写视觉壳。

## 4. P1：报头状态机

目标：报头不再只有 `variant`，而是具备明确状态。

状态定义：

| 状态 | 触发 | 视觉 |
| --- | --- | --- |
| `expanded` | 空会话、首屏、低信息密度 | section 报头，保留 dek/装饰线空间 |
| `compact` | 常规对话、记录页首屏 | compact 报头，保留标题和 tabs |
| `collapsed` | 内容滚动后 | 压缩报头，弱化标题，保留视图切换 |

执行要求：

1. `ChatEditorialShell` 管理状态，不放在路由页。
2. 状态可以由滚动、view、内容密度共同决定。
3. CSS 使用 `chat-editorial-head--expanded/compact/collapsed`，禁止页面散写。

## 8. P1.1：颜色层级门禁

本轮补充判断：复古报刊风格不能只依赖同一米色背景和细边框。正式页面至少需要 5 个视觉层级：

| 层级 | 用途 | Chat 当前落点 |
| --- | --- | --- |
| Canvas | 页面底纸，承接整体空间 | `chat-editorial-page` |
| Masthead | 报头纸，承担页面身份 | `chat-editorial-head` |
| Surface | 内容纸面，承载主体模块 | `chat-editorial-surface` |
| Card | 对话气泡、记录卡、空态卡 | `editorial-chat-bubble`、`chat-records-card` |
| Control | tab、输入栏、footer 操作区 | `PaperButton`、`editorial-chat-inputbar`、`chat-footer` |

门禁：

1. 任一正式页面迁移不能出现 Canvas / Surface / Card 使用同一纯背景色。
2. 卡片层必须同时具备轻边框和纸面阴影，不能只靠虚线框。
3. Footer / Composer 必须和内容区有明确色阶差异。
4. `/decor-preview` 样张与正式页必须同步更新色阶，避免预览和正式页两张皮。
