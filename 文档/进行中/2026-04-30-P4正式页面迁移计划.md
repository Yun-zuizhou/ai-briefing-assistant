## 1. 计划定位

本文件恢复 P4，但不恢复旧 P4 的执行顺序。

P4 当前目标是把 `/decor-preview` 已通过 S5 的复古报刊简报组件，分批迁入正式页面。迁移必须基于新的页面职责：记录归入对话页子页，待办成为信息驱动行动工作台，成长承载用户画像与 AI 分析，我的收束为设置中心。

## 4. 组件迁移边界

### 4.1 允许进入正式页

| 组件 | 使用边界 |
| --- | --- |
| `EditorialMasthead` | 用于对话记录、待办、成长、我的的报头统一；按 `front / section / compact` 规格选择 |
| `EditorialIcon` | 只用于高频操作和入口图标，不扩大到装饰图标泛滥 |
| `StatusBadge` | 用于摘要状态、待办状态、跟进状态、报告状态 |
| `PaperButton` | 用于低风险次级操作，主流程仍需和正式 `Button` 协调 |
| `SectionHeader` | 用于页面区块标题，但要保持语义标题层级 |
| `OrnamentDivider` | 用于报头下方、区块起止、内容组之间的低密度装饰线；每屏建议 1-3 条，禁止堆成花边 |
| `StitchDivider` | 仅用于左右栏或时间线等明确结构分隔，不作为普通页面装饰 |

### 4.2 暂缓进入正式页

| 组件 | 暂缓原因 |
| --- | --- |
| `BookishChip` / `ChipGroup` | 仍需确认是否升级为正式 segmented tabs |
| `BookishCard` / `PaperSheet` | 容器风格可参考，但不能一键替换全部 `domain-card` |
| `SystemBriefCard` | 仍是组合实验模块，业务职责不稳定 |
| `BookishIconSet` | 图标包过大且包含大量偏国风符号，不作为正式入口 |

### 4.3 装饰线强制规范

P4 正式页面迁移不能只替换图标、按钮和卡片。复古报刊风格必须包含可见但克制的“版面线”，否则页面会退回普通浅色卡片 UI。

装饰线使用规则：

1. 报头下方必须有一条横向装饰线，优先使用 `OrnamentDivider ornament="diamond" dashed`。
2. 内容纸面入口建议有一条轻分隔线，优先使用 `OrnamentDivider ornament="none" dashed`。
3. 区块标题下方可用 1px 实线或虚线，但每个移动端首屏总数控制在 1-3 条。
4. 装饰线颜色只能使用 `rgba(139, 90, 43, 0.18-0.28)` 或 `var(--bookish-border)`。
5. 禁止使用复杂传统纹样、水墨纹理、厚重边框或多层花边。
6. 每批迁移截图验收时，必须检查“报头线 / 内容线 / 区块线”是否至少有一类实际可见。

## 5. P4 分批计划

### P4-A0：对话摘要契约适配前置

目标：在迁移对话记录页之前，先把“系统级摘要任务”适配成 Chat 页面可消费的前端契约，避免在 UI 迁移中出现假按钮、假状态或临时硬编码。

判断：

1. 项目已有 `summary_generation_tasks` / `summary_generation_results` 数据表。
2. Edge Worker 已暴露 `/api/v1/system/summary-tasks`、`/summary-tasks/:id`、`/summary-tasks/:id/result`。
3. 当前前端 `apiService` 尚未封装系统摘要任务方法。
4. 当前 `ChatRecordsPanel` 仍使用 `notes + actions`，还没有消费摘要任务。
5. 文档曾规划 `GET /chat/sessions/:id/summary`，但当前代码未见该 Chat 专用端点。

执行步骤：

| 步骤 | 任务 | 文件 | 状态 |
| --- | --- | --- | --- |
| A0-1 | 补 `apiService` 摘要任务适配方法 | `apps/web/src/services/api.ts` | 已完成（实际已存在） |
| A0-2 | 约定 Chat 会话摘要 payload | 本文件、后续组件代码 | 已完成 |
| A0-3 | 将 `ChatRecordsPanel` 契约从 `notes/actions` 改为 `summary/sessions` | `apps/web/src/components/chat/ChatRecordsPanel.tsx` | 已完成 |
| A0-4 | 在 `ChatPage` 传入 sessions 与 session 切换回调 | `apps/web/src/pages/ChatPage.tsx` | 已完成 |
| A0-5 | 只在契约稳定后迁移正式页面视觉组件 | `ChatPage`、样式文件 | 已完成 |

Chat 会话摘要 payload 约定：

```json
{
  "content_type": "chat_session",
  "content_id": 123,
  "title": "<sessionTitle>",
  "summary_kind": "chat_session"
}
```

状态策略：

| 系统状态 | Chat UI 状态 | 处理 |
| --- | --- | --- |
| 无任务 | 未生成 | 显示“生成摘要” |
| `pending_provider` | 待配置 | 显示“摘要服务未配置”，引导 AI 服务设置 |
| `queued` | 排队中 | 禁止重复提交 |
| `running` | 生成中 | `aria-live` 提示 |
| `succeeded` | 已生成 | 拉取 result 展示摘要 |
| `failed` | 失败 | 显示错误和重试 |

验收：

1. 前端有系统摘要任务 API 方法。
2. `ChatRecordsPanel` 不再把“对话中的想法/对话转成的待办”作为记录主结构。
3. 生成摘要按钮只调用真实任务接口，不伪造 LLM 结果。
4. 若 provider 未配置，UI 显示明确状态，不假装生成成功。

## 6. 执行规则

1. 每一批只改对应页面和必要组件，不跨批次顺手重构。
2. 不改后端 API、数据库 schema 和共享类型契约。
3. 不删除旧路由；旧入口先降级或迁出导航。
4. 不把预览样张组件整块复制到正式页面。
5. 不继续扩大 `Bookish*` 组件在正式页面的直接调用。
6. 每批必须保留截图证据和命令结果。
