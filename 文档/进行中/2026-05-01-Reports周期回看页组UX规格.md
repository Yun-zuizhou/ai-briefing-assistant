# 2026-05-01 Reports 周期回看页组 UX 规格

## 1. 页组定位

周期回看页组负责把一段时间内的阅读、记录、收藏、待办和关注变化整理成可回看的解释。

它不是仪表盘，也不是历史日志。

一句话：

> 历史日志告诉用户发生过什么；周期报告解释这些变化意味着什么。

## 2. 页面关系

当前页组：

- `/history-brief`：历史简报，报告档案入口；
- `/weekly-report`：周报，解释一周变化；
- `/monthly-report`：月报，解释一个月变化；
- `/annual-report`：年度报告，解释一年关注、思考和行动。

关系：

```text
历史日志 / 记录 / 收藏 / 待办
-> 周报 / 月报 / 年报生成
-> 历史简报作为档案入口
-> 进入具体周期报告查看解释、依据和导出分享
```

## 3. `/history-brief` 职责

职责：

- 展示周报、月报、年报入口；
- 区分可查看和暂未生成；
- 支持搜索历史周期回顾；
- 进入具体报告页。

非职责：

- 不展示每日系统留痕；
- 不展示完整报告正文；
- 不做趋势仪表盘；
- 不生成报告内容。

## 4. 报告页职责

周报：

- 解释这一周的阅读、记录和行动变化；
- 适合看短周期趋势和下一步建议。

月报：

- 解释一个月内关注、行动和沉淀变化；
- 适合看更稳定的主题变化。

年度报告：

- 回看一年里的关注、思考和行动；
- 适合看长期关键词、年度总结和下一年建议。

## 5. 信息层级

报告页推荐层级：

1. 数据状态：加载、空态、错误、样本不足。
2. 数据可信度：说明是否只展示确认事实。
3. 智能解读：趋势解释、周期总结、行动建议。
4. 事实概览：阅读、记录、收藏、待办、活跃天数等。
5. 变化趋势：热点、关注、成长或行为变化。
6. 依据来源：说明判断来自哪些记录或来源。
7. 导出和分享。

## 6. 文案规则

面向用户使用：

- 周期回看；
- 智能解读；
- 基础汇总；
- 依据来源；
- 数据可信度；
- 已确认事实。

避免：

- 把页面叫仪表盘；
- 用 `LLM`、`payload`、`规则聚合`；
- 把样本不足包装成完整结论；
- 用大量装饰符号强化演示感；
- 让报告页承担即时行动管理。

## 7. 与其他页面边界

和 `/history-logs`：

- 历史日志按天留痕；
- 报告页按周期解释。

和 `/growth`：

- Growth 是成长概览和导航；
- 报告页是具体周期回看。

和 `/profile`：

- Profile 解释“系统如何理解我”；
- 报告页解释“这个周期发生了什么变化”。

和 `/todo`：

- 报告可以给下一步建议；
- 待办页负责行动生命周期。

## 8. 后续改进

短期：

- 在 HistoryBrief 加入报告更新时间；
- 报告依据来源可点击回跳；
- 空态提供“去记录/去简报/去待办”的明确入口。

中期：

- 报告中明确区分事实、推断和建议；
- 支持用户标记“这条总结不准确”；
- 让报告反馈反哺画像和简报推荐。
