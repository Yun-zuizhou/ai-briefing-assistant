# 2026-05-01 ArticlePage 阅读详情页 UX 规格

## 1. 页面定位

阅读详情页不是第二个简报页，也不是行动管理页。它负责承接简报、热点、收藏、历史和报告里的单条内容，让用户完成阅读、核对来源、收藏、追问和必要时转交待办。

技术路由仍为 `/article`，产品语义是“阅读详情”。

## 2. 页面负责

- 展示内容标题、来源、发布时间、作者和阅读状态；
- 展示摘要、正文、标签和相关推荐；
- 提供原文入口；
- 支持收藏、分享和继续追问；
- 对 opportunity 类型内容提供“转成待办”的交接入口。

## 3. 页面不负责

- 不负责每日内容排序；
- 不负责生成简报；
- 不负责管理待办生命周期；
- 不负责把所有推荐内容重新组织成列表页；
- 不承接 Chat 的确认、执行和结果解释。

## 4. 信息层级

```text
阅读详情
-> 标题和来源
-> 阅读状态 / 部分内容提示
-> 操作栏：收藏 / 分享 / 追问 / 原文
-> 字号控制
-> 摘要
-> 正文
-> 标签
-> 相关推荐
-> opportunity 转交待办入口
```

## 5. 关键交互

| 动作 | 所属层级 | 去向 | 要求 |
| --- | --- | --- | --- |
| 打开原文 | 核对来源 | 外部链接 | 失败要给反馈 |
| 收藏 | 沉淀 | Collections | 成功/取消要反馈 |
| 追问 | 理解延展 | Chat | 必须带 `contentRef` 和标题上下文 |
| 转成待办 | 行动交接 | Chat -> Todo/Actions | 只对 opportunity 出现 |
| 相关推荐 | 延伸阅读 | Article | 保留当前阅读心智 |

## 6. 数据契约

阅读详情依赖：

- `contentRef`：跨页面来源引用；
- `title`、`summary`、`content`：阅读主体；
- `sourceName`、`sourceUrl`、`author`、`publishedAt`：来源可信度；
- `detailState`、`detailStateReason`、`missingFields`：内容是否完整；
- `relatedItems`：延伸阅读；
- favorites API：收藏状态和写入结果。

## 7. 当前实现与差距

已完成：

- 页面标题从“文章详情”收口为“阅读详情”；
- 操作栏补齐“追问”入口，并把内容上下文传给 Chat；
- opportunity 的描述改为“转交待办系统”，避免让详情页承担待办管理。

仍有差距：

- 收藏后还没有在页面内展示“去收藏查看”的轻量出口；
- 原文打开失败只有 toast，缺少可复制链接兜底；
- 相关推荐仍是简单列表，未区分同主题、同来源、后续线索；
- 正文缺失时的空状态还偏工程说明。

## 8. 验收清单

- 从简报打开报道后，用户知道自己在阅读详情页；
- 用户能找到原文入口；
- 用户能围绕当前内容追问，Chat 能拿到来源上下文；
- 收藏有明确反馈；
- opportunity 可以转交待办，但详情页不展示完成、延期、提醒等待办生命周期；
- 页面不把相关内容扩展成第二个热点页。
