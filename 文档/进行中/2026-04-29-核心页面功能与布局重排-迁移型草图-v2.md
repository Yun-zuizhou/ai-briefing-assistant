## 1. v2 修订目标

v2 不改变迁移方向，只修正 v1 评估中发现的结构问题。

本版固定以下口径：

1. 对话页只保留两个一级视图：`对话`、`记录`。
2. 对话记录子页只保留两个主功能：`摘要`、`会话`。
3. 原“摘要线索”折叠进摘要卡，不再成为独立区块。
4. 原“对话转成的待办”只保留外链，不在记录页展示完整列表。
5. 待办页首屏最多展示 2 条“可转行动的信息”。
6. `HistoryLogsPage` 不并入对话记录，只进入成长页历史回顾或保留兼容路由。
7. 成长页使用“用户画像概览”，我的页使用“账号状态卡”，避免命名混乱。

| 当前模块 | v2 新归位 | 说明 |

| `ChatRecordsPanel` 对话中的想法 | 记录页 `摘要` 中的“依据片段” | 折叠展示，不独立成列表 |

## 3. R1 对话记录子页 v2

### 3.1 信息架构

```text
ChatPage
  ├─ 对话
  │  ├─ 当前会话流
  │  ├─ 输入区
  │  └─ 会话侧栏或会话入口
  └─ 记录
     ├─ 摘要
     └─ 会话
```

不再设置独立的“历史”一级 Tab。历史会话属于记录子页内部的 `会话` Tab。

### 3.2 低保真草图

```text
对话页
┌────────────────────────────┐
│ 报头：对话                  │
│ [对话] [记录]               │
├────────────────────────────┤
│ 对话视图：保持当前 Chat 主体 │
│ - 消息流                    │
│ - 输入区                    │
│ - 模式 chips                │
└────────────────────────────┘

记录视图
┌────────────────────────────┐
│ 报头：对话记录              │
│ 仅回看对话摘要与历史会话     │
├────────────────────────────┤
│ [摘要] [会话]               │
├────────────────────────────┤
│ 摘要 Tab                    │
│ ┌ 对话摘要卡 ─────────────┐ │
│ │ 会话标题 / 时间          │ │
│ │ 状态：未生成/生成中/完成 │ │
│ │ 要点 / 决策 / 待跟进     │ │
│ │ 依据片段：展开查看       │ │
│ │ 3 条待办已进入待办页     │ │
│ │ [生成摘要] [继续对话]    │ │
│ └────────────────────────┘ │
│ 最近已摘要会话              │
│ - 标题 / 时间 / 查看摘要     │
├────────────────────────────┤
│ 会话 Tab                    │
│ 搜索：关键词 / 日期          │
│ 筛选：全部 / 本周 / 有摘要   │
│ 会话列表                    │
│ - 标题 / 时间 / 消息数       │
│ - 摘要状态 / 继续对话        │
└────────────────────────────┘
```

### 3.3 主路径

| 用户目标 | 路径 |
| --- | --- |
| 继续当前对话 | 对话页 -> 对话 -> 输入或继续消息 |
| 回看上一段对话总结 | 对话页 -> 记录 -> 摘要 -> 查看摘要卡 |
| 给历史会话生成摘要 | 对话页 -> 记录 -> 会话 -> 选择会话 -> 生成摘要 |
| 找到某次历史会话 | 对话页 -> 记录 -> 会话 -> 搜索/筛选 -> 继续对话 |
| 查看对话生成的待办 | 对话页 -> 记录 -> 摘要卡底部链接 -> 待办页 |

### 3.4 状态要求

| 状态 | 处理 |
| --- | --- |
| 无历史会话 | 显示空状态，主按钮回到对话 |
| 摘要未生成 | 摘要卡主按钮为“生成摘要” |
| 摘要生成中 | 显示生成中状态，禁止重复点击 |
| 摘要失败 | 显示失败原因和重试 |
| 摘要过期 | 显示“可重新摘要”弱提示 |

## 4. R2 待办页 v2

### 4.1 信息架构

```text
ActionsPage
  ├─ 今日主行动
  ├─ 可转行动的信息（最多 2 条）
  ├─ 待办列表
  ├─ 后续跟进
  └─ 行动节奏（弱展示）
```

### 4.2 低保真草图

```text
待办页
┌────────────────────────────┐
│ 报头：待办                  │
│ 副标题：把信息变成下一步行动 │
├────────────────────────────┤
│ 今天先推进这 1 件            │
│ - 标题                      │
│ - 来源：对话/收藏/手动       │
│ - 截止 / 风险               │
│ - 为什么现在做              │
│ [完成] [延后] [查看来源]     │
├────────────────────────────┤
│ 可转行动的信息              │
│ 最多 2 条，不做信息流        │
│ - 来源标题                  │
│ - 建议动作一句话            │
│ [转成待办] [忽略] [来源]     │
├────────────────────────────┤
│ 待办事项                    │
│ [今日] [未来] [已完成]       │
│ - 优先级 / 标题 / 截止 / 来源│
├────────────────────────────┤
│ 后续跟进                    │
│ - 对象 / 提醒时间 / 下一步   │
├────────────────────────────┤
│ 行动节奏                    │
│ 连续天数和今日完成弱展示     │
└────────────────────────────┘
```

### 4.3 与 Today 的边界

| 内容类型 | Today 页职责 | 待办页职责 |
| --- | --- | --- |
| 简报内容 | 展示信息本体、价值和推荐理由 | 只展示由简报抽出的可执行动作 |
| 收藏内容 | 收藏、阅读、保留内容 | 判断是否转成待办或跟进 |
| 对话判断 | 可作为今日提醒或上下文 | 形成明确待办、截止、来源 |
| 机会线索 | 发现与解释 | 决定是否执行、何时执行 |

### 4.4 首屏限制

1. 首屏只允许一个主行动卡。
2. “可转行动的信息”最多展示 2 条。
3. 单条信息只保留标题、来源、建议动作和三个操作。
4. 不展示长摘要、不展示全部收藏。

## 7. 组件库修订清单

v2 只新增必要组件，优先复用现有组件。

| 优先级 | 组件/模式 | 处理 |

4. 不把 `JournalPage` 整页迁进任何新页面。

## 8. 样张实施顺序

v2 完成后，可以进入低保真样张。当前低保真样张已接入 `/decor-preview`，顺序如下：

1. `ChatRecordsPanel v2`：验证 `[对话] [记录]` 与记录内 `[摘要] [会话]`。
2. `ActionsPage v2`：验证首屏主行动 + 2 条可转行动信息。
3. `GrowthPage v2`：验证用户画像概览 + 一句话画像 + AI 分析摘要。
4. `MyPage v2`：验证设置化后入口是否清楚。

样张只进入 `/decor-preview`，不直接改正式页面。当前已新增 `EditorialPageReframeSample`，用于一次性展示四个迁移画板。

## 9. v2 验收标准

进入 `/decor-preview` 低保真样张前，需要确认：

1. 对话页没有“历史”一级 Tab。
2. 记录子页没有第三个主功能区。
3. 对话生成的待办不在记录页铺列表。
4. 待办页的可转行动信息最多 2 条。
5. 成长页与我的页的账号/画像命名不冲突。
6. `HistoryLogsPage` 只作为成长历史回顾或兼容路由，不进入对话记录。

满足以上条件后，再恢复组件系统 P4 前置样张。
