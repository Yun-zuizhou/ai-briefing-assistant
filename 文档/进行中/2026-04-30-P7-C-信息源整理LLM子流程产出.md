## 1. 本批目标

在 P7-B 已完成 Today AI 简报 payload 的基础上，继续把信息源整理纳入可控 LLM 子流程。

本批仍不让 LLM 接管全量排序：

1. 规则层继续负责内容抓取、基础排序、候选池构造。
2. LLM 只处理 `worthKnowing + worthActing` 候选集。
3. LLM 只输出主题归并、可信度解释和推荐理由。
4. 失败时继续保留规则 Today。

## 2. 已完成内容

### 2.1 契约补充

更新文件：

- `packages/contracts/src/page-data.ts`

`TodayAiBriefingCluster` 新增可选字段：

```ts
confidenceNote?: string
recommendationReason?: string
```

字段含义：

| 字段 | 含义 | 约束 |
|---|---|---|
| `confidenceNote` | 可信度解释 | 只能基于来源数量、内容一致性、发布时间和来源标签 |
| `recommendationReason` | 推荐理由 | 应引用用户关注、候选内容或行动价值 |

### 2.2 候选源去重

更新文件：

- `apps/edge-worker/src/services/briefing/llm-briefing.ts`

当前去重策略：

1. 候选输入仍来自：
   - `worthKnowing`
   - `worthActing`
2. 按 `contentRef` 去重。
3. 按标题 + 摘要归一化 key 去重。
4. 去重后重新分配候选下标，保证 prompt 中 `sourceIndexes` 稳定。

边界：

- 当前是最小文本归一化，不做跨语言语义去重。
- 规则排序仍保留原顺序，不让 LLM 重新决定全量优先级。

### 2.3 Prompt 约束增强

`llm-today-briefing-v1` prompt 已补充：

1. 需要做主题归并、轻量去重、可信度解释和推荐理由解释。
2. 可信度解释只能基于候选材料，不得声称某来源权威。
3. `topicClusters` 每组输出：
   - `title`
   - `summary`
   - `confidenceNote`
   - `recommendationReason`
   - `sourceIndexes`

### 2.4 后端读取兼容

更新文件：

- `apps/edge-worker/src/routes/dashboard.ts`

新增行为：

1. `payload.aiBriefing.topicClusters[]` 安全规范化时保留：
   - `confidenceNote`
   - `recommendationReason`
2. 字段不存在时保持兼容，不影响旧 payload。

### 2.5 前端展示

更新文件：

- `apps/web/src/services/api.ts`
- `apps/web/src/pages/TodayPage.tsx`

新增行为：

1. API 校验器允许 `confidenceNote` 和 `recommendationReason`。
2. Today AI 主题归并卡片展示：
   - 推荐理由
   - 可信度解释
   - 来源数量

## 3. 当前边界

1. 当前没有新增独立“source organizer”任务表。
2. 当前没有保存重复来源列表，只保存归并后的来源引用。
3. 当前没有对所有 RSS/热点/机会做全量 LLM 处理，只处理 Today 候选集。
4. 当前可信度解释是可读说明，不是风控评分。
5. 当前历史简报只读页尚未接入该展示块。
