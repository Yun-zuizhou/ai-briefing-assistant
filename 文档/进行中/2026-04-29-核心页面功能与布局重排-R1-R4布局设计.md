## 1. 文件定位

本文件承接核心页面功能与布局重排计划的 R1-R4，负责把“记录、待办、成长、我的”四个页面的新职责转成可落地的移动端布局方案。

本文件只做布局设计和组件规划，不直接修改正式页面代码。后续应先在 `/decor-preview` 或并列预览样张中实现，再进入正式页面迁移。

注意：本文件偏目标态布局。正式进入样张前，必须以迁移型草图 v2 为准，优先复用 `JournalPage`、`ActionsPage`、`GrowthPage`、`MyPage`、`ChatRecordsPanel` 当前已有模块，采用移动位置、改名、降级、合并的方式推进，而不是按全新页面重构。

## 2. 全局设计原则

### 2.1 产品原则

1. 页面先回答“用户来这里做什么”，再考虑装饰。
2. 每个一级页面只承担一个清晰主任务。
3. 对话是输入与生成中心，记录是对话的子结果。
4. 待办是信息转行动中心，不是收藏夹，也不是成长打卡页。
5. 成长是系统长期理解用户的地方，不是入口集合页。
6. 我的页是设置中心，不再承载个人沉淀主功能。

### 2.2 移动端布局原则

1. 优先适配 360-430px 宽度。
2. 首屏只放一个主任务和最多两个辅助动作。
3. 触控目标不低于 44px。
4. 重要操作按钮在卡片底部或模块末尾，不夹在长文本中间。
5. 页面不使用嵌套卡片，卡片只用于独立重复项、工具面板和必要容器。
6. 列表信息密度要高于当前样张页，避免每个条目都变成大装饰卡。

### 2.3 视觉原则

1. 继续沿用复古报刊简报体系：米杏背景、棕褐线条、编辑部排版、克制细线。
2. 国风元素只作为辅助点缀，不能作为页面主视觉。
3. 待办页允许比其他页面更“工作台”，视觉上更清晰、硬朗、可扫描。
4. 成长页允许更大篇幅文字和解释，但必须分层，不能变成长文章。
5. 我的页要最安静，像设置页，不做成长页式叙事。

## 3. 导航与路由总方案

### 3.1 建议一级导航

短期建议底部导航仍保持五个入口：

| 入口 | 路由 | 新职责 |
| --- | --- | --- |
| 对话 | `/chat` | 对话、记录子页、历史对话、摘要 |
| 简报 | `/today` | 今日信息与推荐入口 |
| 待办 | `/todo` 或 `/actions` | 信息驱动行动工作台 |
| 成长 | `/growth` | 画像、AI 分析、长期变化 |
| 我的 | `/me` | 设置中心 |

不新增“记录”一级入口。

### 3.2 兼容路由

| 旧路由 | 处理 |
| --- | --- |
| `/log` | 保留兼容，后续可跳转到 `/chat?view=records` |
| `/history-logs` | 保留兼容，入口迁入对话页记录子页 |
| `/history-brief` | 保留，后续作为成长/报告入口的一部分 |
| `/todo` 和 `/actions` | 继续指向待办页 |
| `/profile` | 可作为成长页的详情子页，而不是我的页核心入口 |

## 4. R1：对话记录子页布局设计

### 4.1 页面定位

对话记录子页是对话页的一部分，专门处理“过去对话如何被回看和总结”。

主任务：

1. 查找过去对话。
2. 查看或生成某段对话摘要。
3. 继续某个历史会话。

不处理：

1. 全部笔记。
2. 全部待办。
3. 收藏。
4. 成长分析。

### 4.2 信息架构

```text
ChatPage
  ├─ 当前对话
  ├─ 记录
  │   ├─ 对话摘要
  │   └─ 历史对话
  └─ 当前会话详情
```

### 4.3 页面结构

移动端结构：

```text
[Compact Masthead: 对话记录]
[Segmented Tabs: 摘要 / 历史]

摘要 Tab:
  [当前选中会话摘要卡]
  [生成状态条：未生成 / 生成中 / 已生成 / 失败]
  [摘要正文：要点 / 决策 / 待跟进]
  [操作：重新摘要 / 继续对话 / 复制]
  [相关历史会话]

历史 Tab:
  [搜索框：关键词 / 日期]
  [筛选 Chips：全部 / 本周 / 有摘要 / 有待办]
  [会话列表]
    [会话标题]
    [最近消息摘要]
    [时间 / 消息数 / 是否已摘要]
    [继续 / 查看摘要]
```

### 4.4 首屏布局

首屏应优先展示：

1. 子页标题“对话记录”。
2. 摘要 / 历史切换。
3. 最近一段对话的摘要状态。
4. 一个主操作：生成摘要或继续对话。

### 4.5 组件需求

| 组件 | 用途 | 优先级 |
| --- | --- | --- |
| `ChatRecordSummaryCard` | 展示单会话 LLM 摘要 | C0 |
| `ConversationSummaryStatus` | 展示摘要生成状态 | C0 |
| `ConversationHistoryList` | 展示历史会话列表 | C0 |
| `ConversationSearchBar` | 搜索对话 | C1 |
| `ConversationFilterChips` | 筛选会话 | C1 |

### 4.6 状态设计

| 状态 | 表现 |
| --- | --- |
| 无历史对话 | 引导用户回到对话页开始一次对话 |
| 摘要未生成 | 展示“生成对话摘要”主按钮 |
| 摘要生成中 | 展示进度文案和不可重复提交状态 |
| 摘要失败 | 展示失败原因和重试按钮 |
| 摘要已生成 | 展示要点、结论、待跟进 |

## 5. R2：待办页布局设计

### 5.1 页面定位

待办页是信息驱动的行动工作台。

主任务：

1. 告诉用户今天先推进什么。
2. 展示待办背后的来源信息。
3. 把收藏、内容、机会、对话判断转成可执行动作。

### 5.2 信息架构

```text
ActionsPage
  ├─ 今日主行动
  ├─ 信息转行动
  ├─ 待办列表
  ├─ 跟进与提醒
  └─ 完成反馈
```

### 5.3 页面结构

移动端结构：

```text
[Masthead: 行动工作台]
[今日主行动卡]
  - 标题
  - 来源：来自对话 / 内容 / 收藏 / 手动
  - 为什么优先
  - 截止与风险
  - 操作：完成 / 延后 / 查看来源

[信息转行动区]
  [来源信息卡] -> [建议动作]
  [收藏/机会/对话摘要中的可行动项]

[待办列表]
  [Segmented: 今天 / 之后 / 已完成]
  [Todo item: 优先级 / 标题 / 来源 / 截止]

[跟进与提醒]
  [跟进对象]
  [提醒时间]

[完成反馈]
  [今天完成了什么]
  [下一步建议]
```

### 5.4 首屏布局

首屏只放：

1. 行动工作台标题。
2. 今日主行动卡。
3. 信息转行动入口。

不要在首屏同时展示收藏、跟进、打卡、全部待办。

### 5.5 组件需求

| 组件 | 用途 | 优先级 |
| --- | --- | --- |
| `ActionPriorityBoard` | 今日主行动卡 | C0 |
| `ActionContextCard` | 待办来源上下文 | C0 |
| `CollectedInfoActionCard` | 信息转行动卡 | C1 |
| `ActionDeadlineBadge` | 截止状态 | C1 |
| `ActionFollowUpStrip` | 跟进提醒 | C1 |

### 5.6 视觉方向

待办页不应太柔。建议：

1. 使用更清晰的网格、编号、截止标签。
2. 主行动卡比普通列表更强。
3. 来源信息用轻边框小块，不做大面积解释。
4. 完成态用低饱和状态，不让已完成任务抢视线。

## 6. R3：成长页布局设计

### 6.1 页面定位

成长页是系统长期理解用户、解释变化、沉淀 AI 分析的页面。

主任务：

1. 让用户看到“系统如何理解我”。
2. 让用户看到“我在什么方向上变化”。
3. 为未来附加功能保留空间。

### 6.2 信息架构

```text
GrowthPage
  ├─ 用户画像主面板
  ├─ AI 分析报告
  ├─ 长期关键词与兴趣变化
  ├─ 阶段轨迹
  ├─ 时空胶囊预留
  └─ 周期报告入口
```

### 6.3 页面结构

移动端结构：

```text
[Masthead: 成长]
[用户画像主面板]
  - 当前一句话画像
  - 画像置信度 / 更新时间
  - 关键词组
  - 查看画像详情

[AI 分析报告]
  - 本周观察
  - 行为变化
  - 建议下一步

[长期信号]
  - 兴趣关键词变化
  - 关注强度
  - 最近高频主题

[时空胶囊预留]
  - 写给未来自己的问题
  - AI 给未来自己的总结
  - 纪念节点

[周期报告入口]
  - 周报 / 月报 / 年报
```

### 6.4 首屏布局

首屏应展示：

1. 用户画像主面板。
2. AI 分析一句话。
3. 进入详情的操作。

历史回顾和报告入口下移，不再抢首屏。

### 6.5 组件需求

| 组件 | 用途 | 优先级 |
| --- | --- | --- |
| `GrowthPersonaPanel` | 用户画像大面板 | C0 |
| `AiInsightReportCard` | AI 分析报告卡 | C0 |
| `GrowthSignalList` | 长期信号列表 | C1 |
| `TimeCapsuleSlot` | 时空胶囊预留入口 | C1 |
| `PeriodReportEntryGrid` | 周期报告入口 | C2 |

### 6.6 视觉方向

成长页允许比其他页面更“个人化”，但不能变成装饰墙。

建议：

1. 用户画像面板占首屏核心。
2. AI 分析采用分段报告样式。
3. 时空胶囊使用留白和轻边框，不做强功能卡。
4. 周期报告入口使用小型网格，不作为首屏主功能。

## 7. R4：我的页布局设计

### 7.1 页面定位

我的页是设置中心。

主任务：

1. 管理账号。
2. 管理系统配置。
3. 获取帮助。
4. 退出登录。

不承担：

1. 成长回看。
2. 历史记录。
3. 画像主功能。
4. 周期报告主入口。

### 7.2 信息架构

```text
MyPage
  ├─ 账号状态
  ├─ 偏好设置
  ├─ AI 服务设置
  ├─ 通知设置
  ├─ 支持与关于
  └─ 账号安全
```

### 7.3 页面结构

移动端结构：

```text
[Masthead: 我的]
[账号状态卡]
  - 头像 / 用户名 / 邮箱
  - 登录状态

[设置分组]
  - 基础设置
  - AI 服务设置
  - 通知设置

[支持分组]
  - 帮助反馈
  - 关于

[账号安全]
  - 退出登录
```

### 7.4 首屏布局

首屏应展示：

1. 账号状态卡。
2. 设置分组前两项。

不展示“成长回看”“我的画像”“历史日志”“历史简报”等个人沉淀入口。

### 7.5 组件需求

| 组件 | 用途 | 优先级 |
| --- | --- | --- |
| `AccountStatusCard` | 账号状态 | C0 |
| `SettingsEntryGroup` | 设置分组 | C0 |
| `SettingsEntryItem` | 设置条目 | C0 |
| `DangerActionRow` | 退出登录 | C1 |

### 7.6 视觉方向

我的页要最克制：

1. 卡片数量少。
2. 入口列表紧凑。
3. 只有设置型 icon。
4. 不使用大段文案。
5. 不使用成长页的情绪化表达。

## 8. 跨页面组件与命名建议

### 8.1 组件分组

建议在 `components/decor` 或后续新目录中按场景拆分：

```text
components/decor
  Editorial*

components/chat
  ChatRecordSummaryCard
  ConversationHistoryList
  ConversationSummaryStatus

components/actions
  ActionPriorityBoard
  ActionContextCard
  CollectedInfoActionCard

components/growth
  GrowthPersonaPanel
  AiInsightReportCard
  TimeCapsuleSlot

components/settings
  AccountStatusCard
  SettingsEntryGroup
```

短期可以仍放在现有目录，但正式迁移前建议按业务域拆分，避免 `decor` 继续承载所有场景组件。

### 8.2 图标语义

| 语义 | 图标建议 |
| --- | --- |
| 对话摘要 | `briefing` |
| 历史对话 | `archive` |
| 继续对话 | `send` |
| 待办主行动 | `chevron-diamond` 或新增 `target` |
| 来源信息 | `inbox` |
| 成长画像 | 可新增 `persona` |
| AI 分析 | 可新增 `spark` 或 `editorial` |
| 设置 | `settings` |

新增图标必须继续遵守 24x24、2px、单线描边、圆角、固定色值。

## 10. 样张实现顺序

| 顺序 | 样张 | 原因 |
| --- | --- | --- |
| 1 | 对话记录子页样张 | 记录归属变化最大，是当前架构核心调整 |
| 2 | 待办页行动工作台样张 | 待办页需要重新建立独特性 |
| 3 | 成长页 AI 分析样张 | 内容承载重，需要先验首屏层级 |
| 4 | 我的页设置中心样张 | 风险最低，但需要清重复入口 |
| 5 | 导航与路由样张 | 等四页结构稳定后再决定 |

## 11. 验收条件

1. 四个页面的首屏主任务清晰。
2. 记录不再作为一级主页面设计。
3. 待办页和 Today 的“值得行动”不重复。
4. 成长页和我的页不重复。
5. 每个页面都有明确组件清单。
6. 每个页面都有空状态、加载态、错误态方向。
7. 设计完成后可以继续制作 `/decor-preview` 页面重排样张。
