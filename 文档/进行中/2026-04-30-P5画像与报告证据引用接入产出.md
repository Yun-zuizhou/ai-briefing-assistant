# P5 画像与报告证据引用接入产出

日期：2026-04-30

## 本次目标

把上一阶段定义的多态引用和 `evidence_refs` 正式接入画像与报告生成链路，使 LLM 生成的用户画像、后续报告结论具备可追溯证据。

## 已完成内容

### 1. D1 迁移

新增迁移：

- `infra/cloudflare/d1/migrations/0025_add_profile_report_evidence_refs.sql`

新增字段：

- `user_profiles.status`
- `user_profiles.provider_name`
- `user_profiles.model_name`
- `user_profiles.evidence_refs_json`
- `user_profiles.error_message`
- `reports.evidence_refs_json`
- `reports.generation_source`
- `reports.provider_name`
- `reports.model_name`

约束：

- `evidence_refs_json` 必须是合法 JSON。
- `status` 约束为 `ready | failed`。
- `generation_source` 约束为 `rules | llm`。

### 2. 画像 LLM 生成服务

新增服务：

- `apps/edge-worker/src/services/profile-generation.ts`

能力：

- 从最近记录、收藏、已完成待办、历史行为中构建候选 `EvidenceRef`。
- 构建画像生成 Prompt，要求模型只返回严格 JSON。
- 解析模型输出：
  - `personaSummary`
  - `growthKeywords`
  - `keyInsights`
  - `evidenceIndexes`
- 只允许模型通过 `evidenceIndexes` 选择服务端提供的候选证据，不允许模型自行编造引用。
- 生成完成后写入 `user_profiles`。
- 调用过程走 `loggedChatCompletion`，会进入 `llm_invocations` 调用日志。

### 3. 画像接口

更新接口：

- `GET /api/v1/preferences/profile`
- `POST /api/v1/preferences/profile/generate`

`GET` 行为：

- 优先读取已生成的 `user_profiles` 结果。
- 如果没有生成结果，继续使用规则画像兜底。
- 缓存读取失败时降级，不影响画像页打开。

`POST` 行为：

- 使用当前用户已配置的 AI provider。
- 调用 LLM 生成画像。
- 写入 `user_profiles`。
- 返回画像文本、关键词、洞察和证据引用。

返回新增字段：

```json
{
  "persona_summary": "你正在把 AI 信息输入转化为记录、行动和复盘。",
  "growth_keywords": ["AI", "记录", "行动"],
  "key_insights": ["近期证据集中在 LLM 接入。"],
  "persona_version": "llm-profile-v1",
  "persona_provider": "deepseek",
  "persona_model": "deepseek-v4-flash",
  "evidence_refs": [],
  "ai_generated": true
}
```

### 4. 报告证据引用

更新服务：

- `apps/edge-worker/src/services/reports/builder.ts`
- `apps/edge-worker/src/services/reports/store.ts`
