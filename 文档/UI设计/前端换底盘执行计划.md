# 前端换底盘执行计划

> 目标：基于 figma 导出的组件体系重建前端，保留项目的 API 层、鉴权、意图识别等运行逻辑。
> 旧前端 `apps/web/` 保留不动，新前端从 `apps/web-v2/` 起步。

---

## 一、目录与备份策略

```
项目根目录/
├── apps/web/              ← 当前正式前端（保留，不动，继续运行）
├── apps/web-v2/           ← 新前端（从头搭建）
└── Untitled/              ← figma 原始导出（只读参考，不动）
```

**规则**：
- 任何时候旧前端都可回退
- figma 原始导出不做任何修改，只从中复制需要的文件
- 新旧前端可以同时运行（不同端口），验证通过后再切换路由

---

## 二、分步执行

### Step 1 — 建立骨架

**输入**：`Untitled/src/`（figma 导出）
**输出**：`apps/web-v2/` 可启动的空骨架

**做什么**：

1. 初始化项目
   - 在 `apps/web-v2/` 下 `npm create vite@latest`（React + TypeScript）
   - 安装依赖：`tailwindcss`、`react-router`、`lucide-react`
   - 把 figma 导出的 `tailwind.config` 搬过来

2. 清洗 shadcn/ui
   - 从 `Untitled/src/app/components/ui/` 中只保留需要的 12 个：`button`、`card`、`badge`、`input`、`textarea`、`tabs`、`calendar`、`separator`、`dialog`、`switch`、`avatar`、`skeleton`
   - 删除其余 36 个（accordion、carousel、drawer、menubar、sidebar 等）

3. 清洗业务组件
   - 从 `Untitled/src/app/components/` 中把页面组件复制到 `pages/`
   - 从 `Untitled/src/app/components/` 中把通用组件（PageHeader、PageContainer、InfoCard、BottomNav、ArticleCard 等）复制到 `components/`
   - 删除组件内的硬编码 mock 数据，替换为空 props

4. 搭建路由
   - 创建 `App.tsx`：BrowserRouter + Routes
   - 16 个页面路由 + 懒加载
   - 先全部指向空占位组件，确认路由通畅

5. 引入设计 tokens
   - 把 `design-md/DESIGN.md` 中的颜色/字体/间距/圆角/阴影映射为 Tailwind tokens
   - 保留 `LXGW WenKai` 字体加载

**验证点**：`npm run dev` 启动，能看到 16 个页面路由，每个页面显示占位文字

---

### Step 2 — 搬迁基础能力层（不改视觉）

**输入**：`apps/web/src/services/`、`apps/web/src/types/`、`apps/web/src/hooks/`、`apps/web/src/context/`
**输出**：新前端有完整的 API 调用和状态管理能力

**做什么**：

1. 搬迁 API 层
   - 复制 `apps/web/src/services/` → `apps/web-v2/src/services/`
   - 复制 `apps/web/src/types/` → `apps/web-v2/src/types/`
   - 复制 `packages/contracts/` 中的 page-data 类型（或直接 import 包）

2. 搬迁鉴权
   - 复制 `context/AppContext.tsx` → v2
   - 复制 `pages/LoginPage.tsx` + `useLoginPageLogic.ts` → v2
   - 复制 `pages/WelcomePage.tsx` + `useWelcomePageLogic.ts` → v2
   - 在 v2 的 `App.tsx` 中加上 `ProtectedRoute` 鉴权守卫
   - LoginPage 和 WelcomePage 保留 figma 的布局结构，但接入真实的鉴权逻辑

3. 搬迁核心 hooks
   - `useChatLogic.ts` → v2
   - `useTodayPageLogic.ts` → v2
   - `useActionsPageLogic.ts` → v2
   - `useGrowthPageLogic.ts` → v2
   - 其他页面的 useXxxLogic → v2

4. 搬迁装饰组件
   - 从 `apps/web/src/components/decor/` 搬：`EditorialMasthead`、`DecorFrame`、`StatusBadge`、`PaperButton`、`OrnamentDivider`、`Dateline`、`SectionHeader`
   - 这些组件保留在 v2 中，作为 figma 组件体系的补充

**验证点**：能登录、能看到 API 返回的数据（console 打印即可，先不渲染到 UI）

---

### Step 3 — 逐个页面对接数据（核心工作）

**原则**：改一个测一个，不批量改。

**每个页面的操作步骤**：
1. 把页面组件的 mock 数据换成 `useXxxLogic` hook 返回的真实数据
2. 把数据字段映射到 figma 设计好的组件结构上
3. 补充空状态/加载态/错误态（参考项目当前的 state 处理方式）
4. 自测通过后进入下一个

**页面顺序**（按依赖关系）：

| 批次 | 页面 | 依赖 | 预计工时 |
|------|------|------|----------|
| 1 | `/today` | API: `getTodayPageData()` | 最大的一页 |
| 2 | `/chat` | API: SSE + `useChatLogic` | 最复杂的一页，需要把意图识别交互挂到 figma 的对话气泡上 |
| 3 | `/todo` | API: `getActionsOverview()` | 中等 |
| 4 | `/growth` | API: `getGrowthOverview()` + `getActionsOverview()` | figma 布局最好，对接最快 |
| 5 | `/me` | `AppContext.user` | 最简单，无独立 API |
| 6 | `/article` | API: `getContentDetail()` | 中等 |
| 7 | `/collections` | API: `getFavorites()` | 新页面 |
| 8 | `/conversation-history` | API: `getChatSessions()` | 新页面，figma 有完整设计 |
| 9-16 | 其余 8 个页面 | 各自 API | 较轻量 |

---

### Step 4 — 意图识别交互注入（对话页特有）

这是整个换底盘中最关键的一步。Figma 的 ChatPage 只有静态 mock 对话，需要注入完整的意图识别链路。

**做什么**：

1. 消息状态映射
   - figma 的消息只有 `role: 'user' | 'assistant'`
   - 项目有 7 种 `ChatMessageState`：`sending` → `recognized` → `pending_confirmation` → `confirmation` → `executed` → `error`
   - 在 v2 的 MessageItem 上增加 `messageState` 字段，同时更新视觉

2. 注入 PendingConfirmationCard
   - 项目组件搬迁到 v2
   - 在 figma 的对话流中找到合适位置渲染（助理消息后）

3. 注入 ResultSummaryCard
   - 项目组件搬迁到 v2
   - 替换 figma 的静态 ConversationSummaryCard

4. 注入可操作按钮（纠正 + 跳转）
   - v2 的 `buildCorrectionQuickActions` 逻辑
   - 按钮文案用 v2 的 LLM 生成方案（参考 `行动建议v2-后端改动方案.md`）

5. 输入区对接 ComposeMode
   - 把项目的 5 种模式（智能/待办/想法/碎片/聊天）挂到 figma 的输入框上

**验证点**：在对话中输入"提醒我明天交报告" → 意图识别 → 确认/执行 → 可操作按钮 → 跳转到 /todo

---

### Step 5 — 切换上线

**灰度切换策略**：

1. 给 v2 页面单独的路由前缀 `/v2/today`、`/v2/chat` 等
2. 旧前端和 v2 并行运行
3. 逐个验证 v2 页面：
   - 页面加载正常
   - API 调用正确
   - 交互功能完整
   - 移动端/桌面端都正常
4. 全部验证通过后，把 `/today` 等路由指向 v2，旧前端只保留 `/v1/` 回退入口
5. 观察一段时间无问题后，归档 `apps/web/`

---

## 三、不动的东西

| 不动 | 原因 |
|------|------|
| `apps/edge-worker/` 后端代码 | API 契约不变，前端换了后端不需要动 |
| `packages/contracts/` | 前后端共享类型，不动 |
| `app/` Python legacy | 保留兼容 |
| `apps/web/` 旧前端 | 保留运行，直到 v2 完全接管 |
| `DESIGN.md` | visual tokens 已足够 |
| `文档/UI设计/` 下的规格文件 | figma 已经读了这些文件 |

---

## 四、风险控制

| 风险 | 对策 |
|------|------|
| Tailwind 和项目 CSS 变量体系冲突 | v2 只用 Tailwind + 少量 CSS 变量（颜色/字体）。项目的 `surfaces.css` 等大文件不搬 |
| 意图识别交互在 Tailwind 体系下视觉效果不对 | 优先保留功能正确，视觉微调放后续 |
| 鉴权逻辑搬迁出错 | LoginPage 是第一个搬迁的页面，出问题立刻发现 |
| 页面太多、战线太长 | 只搬迁核心 5 页面后就可以灰度切换，其余 11 个页面边跑边补 |
